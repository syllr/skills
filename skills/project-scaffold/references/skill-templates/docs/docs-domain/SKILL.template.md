# docs-domain — 领域模型文档

## 定位与管辖文档

本 skill 负责 docs/L2/domain/ 下的业务域总文档 DOMAIN-MAP.md 与每个业务域的
{域}.md。总文档只登记业务域清单、映射图与域间依赖关系；域文档负责一个业务域内的聚合、约束、领域操作、跨聚合服务、状态机、领域事件与跨域接口。

- 一个 skill 两种产物、两份模板：[assets/DOMAIN-MAP.template.md](assets/DOMAIN-MAP.template.md)
  管总文档，[assets/DOMAIN.template.md](assets/DOMAIN.template.md) 管业务域文档；本 skill 不另行维护章节骨架，生成或更新任何产物前先读取对应模板。
- 文档体系按 L1 → L2 → L3 编排，跨层漂移由 align-docs skill 统一调度。

## 读取

- 读取目标文档及其所在目录中的现有内容，区分总文档与业务域文档，保留仍然有效的事实。
- 读取 L1 的 docs-business 产物（业务流程），核对业务能力及其状态；标记为待规划的能力不进入领域模型。
- 读取领域层代码、公共类型、接口与事件定义，使用 File:Line 作为事实依据；不以推测补齐缺失对象。
- 读取与领域对象相关的应用架构、数据架构和接口信息，识别跨文档关系与下游影响。
- 读取既有文档时只提取有效内容，结构按模板重建；源缺失时明确报告，不臆造。

## 生成与更新

生成与更新走同一条流程：先读模板，再扫目标位置判断有无既有文档或同定位的旧产物，有则更新、无则新建。

1.
判定本次目标是总文档还是单个业务域文档，读取对应模板的完整骨架作为写作基准：总文档见 [assets/DOMAIN-MAP.template.md](assets/DOMAIN-MAP.template.md)
，业务域文档见 [assets/DOMAIN.template.md](assets/DOMAIN.template.md)。
2. 扫描目标位置（`docs/L2/domain/` 及其所在目录），判断有无既有总文档、业务域文档或同定位的旧产物；有则先建立变更清单，对照代码、L1
   产物与关联文档区分仍有效事实、已删除内容和新增内容。
3. 扫描 L1 业务产物、领域代码、相关架构文档和目标旧文档，建立可追溯的事实清单。
4. 先写总文档的业务域边界与关系，再为每个实际业务域生成独立文档；更新时新增、删除或合并业务域须同步总文档的业务域清单与映射关系。
5. 对每个实体、约束、领域操作、状态、事件与接口核对代码或上游文档；没有来源的概念不写入。
6. 重新核对聚合、领域操作、状态、事件和跨域接口的引用，删除已失效的交叉引用。
7. 跨模块交互、永久参数、精度分层与坑位四项中命中两项时，在对应域文档内单列小节展开并精简正文，不另起目录、不外链；建模方法、聚合边界或复杂度是否需单列小节存在真实歧义时询问用户。
8. 按完成判定校验，并按联动规则同步受影响文档；发现源冲突时以代码或已确认事实为准并报告。

## 联动

- L1 业务能力、用户故事或能力状态变化时，先更新 docs-business（业务流程），再更新本目录对应产物。
- 领域对象、聚合边界或领域事件变化时，联动 docs-data-architecture 的存储映射和 docs-application-architecture 的模块映射。
- 业务域新增、删除或合并时，同步总文档的业务域清单与映射关系，并通知 align-docs skill 处理跨文档一致性。
- 高复杂度内容在对应域文档内单列小节展开，不外链到其他目录。
- 待规划能力不得在 inbound-ops、docs-application-architecture、docs-structure、openapi 等实现视图留下内容。
- 跨层扫描、漂移分诊和生成顺序由 align-docs skill 编排，本 skill 只处理本目录产物。

## 完成判定

- 总文档与业务域文档分别符合 [assets/DOMAIN-MAP.template.md](assets/DOMAIN-MAP.template.md)
  与 [assets/DOMAIN.template.md](assets/DOMAIN.template.md) 的结构、标题层级和链接要求。
- 总文档业务域清单中的业务域与目录内实际域文档一一对应，新增、删除或合并没有漏登记。
- 聚合、实体、值对象、约束、领域操作、状态、事件和接口均能追溯到代码或上游文档。
- 能力状态为待规划的业务域没有对象、操作、状态机、事件或接口残留。
- 领域操作、状态变化、事件和图示相互一致，跨域服务与数据设计没有越界内容。
- 与 docs-business、docs-data-architecture、docs-application-architecture 的引用方向和内容一致。

## 边界

- 物理存储与领域到存储映射归 `docs-data-architecture`，应用模块划分归 `docs-application-architecture`。
- 禁止自创实体、值对象、事件、状态、接口或业务规则；接口与对象须能回到代码或上游文档，跨聚合只按既有标识引用。
