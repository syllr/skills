# docs-draft — 漂移清单

## 定位与管辖文档

`docs/drift/` 是漂移清单目录，一份清单只承载一个文档的漂移项，目录内不出现清单以外的文件。本 skill 是该目录清单的落盘、更新与清账入口。

本 skill 是纯记录者：差异由 `align-docs` 判定后交给本 skill 落盘，清单内容必须与调用方给出的判定一致；本 skill
不重新判定差异、不改任何层文档正文、不做修复。

生成或重建清单前，先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，按其中表头、字段规则与文件命名落盘；本 skill 不在正文重复模板结构。

前置：`align-docs` skill 已完成链式判定或全量对齐并给出逐条差异。

## 读取

1. 先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，确认字段规则与文件命名。
2. 列出 `docs/drift/` 确定在途清单；已有清单读取全文，保留仍未修复的行。
3. 读调用方给出的逐条差异（位置、差异、漂移原因），核对其指向的文档与 `align-docs` 判定一致。
4. 检查清单当前状态、已修复行与实际进展是否一致。

## 生成与更新

生成与更新走同一条流程：先读模板，再扫目标位置判断有无既有文档或同定位的旧产物，有则更新、无则新建。差异由 `align-docs`
判定后交给本 skill 落盘，本 skill 不重新判定。

1. 先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，确认字段规则与文件命名；再扫描 `docs/drift/` 判断目标文档是否已有清单。
2. 确认目标文档的管辖 skill 与扫描方式（链式判定 / 全量对齐），据此确定文件名与元信息，按文件命名规则确定 `<doc>.md`。
3. 无既有清单：按模板表头逐条新建写入差异。
4. 有既有清单：读取旧内容，按定位做增量追加或结构重建，保留仍未修复的行；用户决断由处置方回写，本 skill 只按回写结果落盘，不改判。
5. 位置与差异必须带可定位信息，漂移原因按调用方判定填；用户决断列一律留空，状态一律 `待修复`；写入后删除模板中的 HTML
   生成提示注释；调用方未给出的信息不补造，位置或代码事实缺失时先退回 `align-docs` 问清，不自行推断。
6. 每修一条立即把该行状态改为 `已修复`，不在清单内追加过程记录；全部行状态为 `已修复` 后删除该清单文件，空目录一并删除。
7. 复读清单，核对表头六列、行号递增、状态合法、文件命名正确，复查目录内无残留的 `已修复` 清单，并报告落盘清单。

## 联动

- 差异判定、严重度校准、逐条问用户决断、修复调度与最终汇总归 `align-docs` skill；本 skill 只承接它的落盘请求。
- 文档正文的修改与重建归该文档的管辖 skill（管辖关系见根 `AGENTS.md` §3）；本 skill 不动正文。
- 发现差异实为实现 bug 时退回 `align-docs`，不由本 skill 转交代码修改。

## 完成判定

格式与结构纪律（正文无加粗与 emoji、无 SSOT 或单一事实源字样、无模板说明与未替换元变量、章节编号连续不跳号、相对链接可解析、跨文档章节引用无死链、不补写
frontmatter）见根 `AGENTS.md` §2.8，各文档不重复列出；以下为本文档专有判定，全部通过才算完成。

- 每份清单的文件命名、四行元信息、表头六列与状态取值均符合 [assets/TEMPLATE.md](assets/TEMPLATE.md)。
- 每行的位置与差异可定位到具体文件与位置，代码事实带 `File:Line`，无凭空补造。
- 漂移原因与调用方判定一致；用户决断列在扫描阶段为空，状态只取 `待修复` 与 `已修复`。
- 目录内无状态为 `已修复` 的残留清单，清空后文件与空目录已删除。

## 边界

- 只维护 `docs/drift/` 的漂移清单；不生成层文档正文，不改业务代码，不做修复。
- 不重新判定差异、不校准严重度、不代替用户决断；判定与调度一律退回 `align-docs`。
- 清单是过程态，不沉淀定型知识，也不作为永久决策记录；历史归 git log。
- 跨文档使用相对 Markdown 链接或自然引用，不设置聚合式相关文档章节。
- 不自动 commit 或 push。
