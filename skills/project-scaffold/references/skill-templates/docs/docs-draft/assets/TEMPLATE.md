# 漂移清单目录模板

## 1. `<doc>.md` 漂移清单

<!-- 生成提示:begin -->
目标结构为中文标题、四行元信息，以及唯一一张表；文件名取被漂移文档的相对路径去掉 `docs/` 与扩展名，层级用短横线连接（如
L2-DATA-ARCHITECTURE.md）。`{...}` 是待替换的元变量，不留在产物中。

- H1：`# 漂移清单 — {被漂移文档路径}`。
- 四行元信息：被漂移文档（docs/ 下的相对路径）、管辖 skill（该文档的管辖 skill 名）、扫描时间（YYYY-MM-DD）、扫描方式（链式判定 /
  全量对齐）。
- 表：列见下方表头。

<!-- 生成提示:end -->

| # | 位置 | 差异（文档 vs 代码） | 漂移原因 | 用户决断 | 状态 |
|---|------|----------------------|----------|----------|------|

## 2. 字段规则

<!-- 生成提示:begin -->
`#` 在清单内从 1 递增，不复用，删除行也不重排；位置可定位到具体文件与位置，跨文件差异拆成多行；差异并排写出文档陈述与代码事实，代码侧带
File:Line；漂移原因取 代码重构未同步 / 需求变更 / 实现简化 / 契约理想与实现差距
等，一句话说清；用户决断在扫描阶段留空，处置阶段由用户逐条填写（以文档为准 / 以代码为准 / 逐条判断）；状态只取 `待修复`（默认）与
`已修复` 两态。
<!-- 生成提示:end -->

## 3. 落盘与清理

<!-- 生成提示:begin -->
一份清单只承载一个文档的漂移项，文件内只有一张表；全部行状态为 `已修复` 后删除该文件，空目录一并删除；清单是过程态，不沉淀定型知识，也不作为永久决策记录。
