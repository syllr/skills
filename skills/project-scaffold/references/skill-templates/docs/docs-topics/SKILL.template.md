# docs-topics — 专项文档

## 定位与管辖文档

`docs/topics/` 是链外独立文档域，承载专项单篇。单篇回答一个具体系统级问题，内容跨越 L1-L3，但不参与链内
L1 → L2 → L3 的生成与传播编排；目录内不设索引文件，单篇清单由引用方文档承担。

本域的增删改由用户直接调本 skill。链上某层变化确实牵连到本域时，由该层 skill 在联动里指明，本 skill 据此更新对应单篇。

- 目标文档结构以 [assets/TEMPLATE.md](assets/TEMPLATE.md) 为准，章节骨架与逐节规则不在本 skill
  维护；生成或更新单篇前必须先读取该模板，并沿用其中的章节编号、标题层级、结构与生成提示。

## 读取

- 读取目标单篇及目录内其他单篇，确认本次要新增、更新、合并还是删除的文件。
- 读取关联代码并保留 File:Line 依据，识别系统级问题涉及的调用、事件、状态和接口。
- 读取 docs-architecture 的应用与系统清单，读取 docs-domain 的领域实体、领域服务、状态与事件，读取 outbound-ops
  的外部契约和 inbound-ops 的对外接口。
- 读取既有单篇时提取仍然有效的事实，按模板重建；不复制其他文档的正文。
- 源文件或项目事实缺失时先报告，不用臆造应用、实体、事件、状态或接口。

## 生成与更新

生成与更新走同一条流程：先读模板，再扫目标位置判断有无既有文档或同定位的旧产物，有则更新、无则新建。本域增删改由用户直接调本
skill。

1. 先读 [assets/TEMPLATE.md](assets/TEMPLATE.md) 的骨架，再扫描 `docs/topics/`
   及目录内其他单篇，确认本次要新增、更新、合并还是删除的文件。
2. 无既有单篇：单篇使用 kebab-case 文件名，扫描关联代码、架构、领域模型、外部契约和对外接口，建立本次系统级问题的事实边界后新建。
3. 有既有单篇：读取旧单篇、模板和所有关联源，建立变更与影响清单，对照代码和关联源区分仍有效的系统流程、已删除内容与新增内容，更新正文、图表、接口引用和状态变化。
4. 只围绕一个系统级问题组织单篇，按模板写应用级交互、应用内部协作、实体状态变化和相关接口；需要拆分或合并时重新确认单篇边界。
5. 按跨模块交互、永久参数、精度分层与坑位四项判定是否需要单列专项；命中两项时将细节交由本 skill
   承载，其他文档只保留摘要与自然引用；系统级问题边界确实存在歧义时询问用户。
6. 新增、删除、改名或合并单篇时，核对目录内无残留旧文件，并检查引用该单篇的文档无死链。
7. 重新执行完成判定并检查与 docs-architecture、docs-domain、outbound-ops、inbound-ops 的引用一致性。

## 联动

- 应用或系统边界变化时，先同步 docs-architecture，再检查本目录单篇的应用级时序图。
- 领域实体、领域服务、状态或事件变化时，联动 docs-domain，并更新相关单篇的内部流程与状态流转。
- 外部服务或契约变化时，联动 outbound-ops；对外接口变化时，联动 inbound-ops。
- 跨文档引用、目录残留与死链由本 skill 自行核对；链上某层变化牵连到本域时，由该层 skill 在联动里指明，再由本 skill 更新受影响单篇。
- 专项引用 L1 至 L3 文档，相关文档不反向建立专项链接；发现入口由引用方文档的自然引用承担。

## 完成判定

- 每篇单篇与 [assets/TEMPLATE.md](assets/TEMPLATE.md) 的章节编号、标题层级和固定结构一致，逐节按各节生成提示核对，且没有模板未定义的内容。
- 每篇单篇只回答一个系统级问题，文件命名符合 kebab-case，目录内无残留或同名文件。
- 应用级时序图、应用内部流程、实体状态流转与接口内容和图示均能追溯到现有代码或关联文档，不含超出源事实的推断，也不复制关联文档正文。
- 与 docs-architecture、docs-domain、outbound-ops、inbound-ops 的引用方向和内容一致。

## 边界

- 一篇单篇只回答一个具体系统级问题，不承载整个平台的全量功能说明；禁止自创应用、实体、事件、状态或接口。
- 不在目录内新建索引文件。
- 本 skill 只由用户显式调起（斜杠命令或明确指令）；AI 不得自行新建、删除或改名专项单篇，链上联动只更新既有单篇。
