# docs-research — 选型与验证调研文档

## 定位与管辖文档

`docs/research/` 是链外独立文档域，承载选型、对比与技术验证调研单篇。每篇只承载一个调研主题的完整论证，内容跨越
L1-L3，但不参与链内 L1 → L2 → L3 的生成与传播编排；目录内不设索引文件；最终选型结论交
`docs-technology-architecture` skill 落盘到 `docs/L2/TECHNOLOGY-ARCHITECTURE.md`。

本域的增删改由用户直接调本 skill。链上某层变化确实牵连到本域时，由该层 skill 在联动里指明，本 skill 据此更新对应单篇。

- 目标文档结构以 [assets/TEMPLATE.md](assets/TEMPLATE.md) 为准，本 skill 不另行维护章节骨架；生成或更新单篇前先读取该模板，按其骨架写入。

## 读取

- 读取目标调研及目录内其他调研，确认本次要新增、更新、合并还是删除的文件。
- 读取技术架构文档 docs-technology-architecture 的现有结论、约束和关联章节，作为调研的输入与结论去向。
- 读取候选官网、项目代码、部署或验证环境资料、测试数据和可复现产物；每项外部事实保留来源链接或 File:Line。
- 读取既有调研时提取有效的对比、验证、成本和风险事实，按模板重建，不把文档演进历史写回正文。
- 候选、验证环境或结论依据缺失时先报告，不用推测填充证据。

## 生成与更新

生成与更新走同一条流程：先读模板，再扫目标位置判断有无既有文档或同定位的旧产物，有则更新、无则新建。本域增删改由用户直接调本
skill。

1. 先读 [assets/TEMPLATE.md](assets/TEMPLATE.md) 的骨架，再扫描 `docs/research/` 及目录内其他调研，确认本次要新增、更新、合并还是删除的文件。
2. 无既有调研：单篇使用 kebab-case 文件名，扫描候选来源、对比维度、技术架构结论和项目验证环境，确定调研问题与可验证目标后新建。
3. 有既有调研：读取旧调研、模板、技术架构结论和全部验证源，建立变更清单，对照候选版本、代码、验证环境、成本与风险依据，区分仍有效结论和已失效证据，更新对比、验证结果、成本、风险、结论及附录证据。
4. 按模板组织背景、候选对比、POC、成本、风险合规和结论；对比表是候选与维度的主记录。
5. POC 至少覆盖代码、文档、流程设计和性能等验证维度；未覆盖的维度显式记录状态与原因，不用空泛文字替代证据。评估接入、运维、许可证成本以及许可证、数据、供应商锁定风险；没有结论时先补充依据。
6. 候选或验证维度不足、目标不可判定、成本数据缺失或推荐存在真实分歧时询问用户。
7. 新增、删除、改名或合并调研时，核对目录内无残留旧文件，并检查引用该调研的文档无死链。
8. 最终推荐与选型理由交 `docs-technology-architecture` skill 落盘到 `docs/L2/TECHNOLOGY-ARCHITECTURE.md`（推荐变化时同样交其更新），本
   skill 不改该文档正文；重新执行完成判定并检查与 `docs-technology-architecture` 的单链关系。

## 联动

- 技术架构中的选型约束、存储或基础设施结论变化时，读取 `docs-technology-architecture` 并更新相关调研。
- 调研推荐变化时，把最终选型结论交 `docs-technology-architecture` skill 落盘；调研保留论证过程，结论不反向复制到其他实现文档。
- 候选代码、接口或部署验证变化时，按实际来源更新证据和复现信息。
- 跨文档引用、目录残留与死链由本 skill 自行核对；链上某层变化牵连到本域时，由该层 skill 在联动里指明，再由本 skill 更新受影响单篇。
- 研究证据、文档合并和改名等演进信息遵循项目文档约定，不在正文重复维护变更记录。

## 完成判定

- 单篇符合 [assets/TEMPLATE.md](assets/TEMPLATE.md) 的结构、标题层级和链接要求。
- 单篇围绕一个主题，候选与对比维度有明确依据；单候选例外和多维度验证均有可复现证据。
- POC 的验证范围、环境、结果和复现方式完整，未覆盖项有明确状态与原因。
- 成本、风险与合规均有内容或依据，结论能追溯到对比和验证证据。
- 最终推荐已交 `docs-technology-architecture` skill 落盘，本域只保留论证过程，两者互不复制正文。

## 边界

- 技术架构选型结论归 `docs-technology-architecture`，本域只保留论证过程，不反向复制。
- 一篇调研只承载一个选型、对比或技术验证主题；不在目录内新建索引文件，不复制单篇正文。
- POC 或验证缺失时不得把未经验证的内容写成确定结论；证据必须能回到代码、官方来源或可复现产物。
