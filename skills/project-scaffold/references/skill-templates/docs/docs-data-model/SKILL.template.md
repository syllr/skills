# docs-data-model — L2 数据建模文档

## 定位与管辖文档

- 管辖 docs/L2/DATA-MODEL.md 的读取、生成、更新与校验，回答数据模型与其数据资产如何对应、存储如何组织、介质之间如何锚定、数据如何流转。
- 本文档属于 L2 架构层；整仓文档按 L1 → L2 → L3 生成，生成下层前先读上层已落盘产物。
- 用户要求生成、更新、重建、编辑或校验 DATA-MODEL，或领域、存储、集成产物变化需要联动时，使用本 skill。
- 目标文档结构以 [文档模板](assets/TEMPLATE.md) 为准，本 skill 不另行维护章节骨架。
- §3 是模型关系（ER）章，以数据模型为节点画模型间引用。
- 数据模型一律是业务数据模型：技术数据不单独成模型，作为所属业务模型的技术资产列出；§3 模型关系（ER）只画业务数据，各模型章的关系图含该模型全部资产。
- §4 起是逐数据模型章：模型有几个就写几章（与 §2.1 的模型一一对应），标题写模型名，编号从 4 起顺延。

## 读取

1. 读取现有 docs/L2/DATA-MODEL.md，提取仍然有效且有来源支撑的信息。
2. 读取 docs/L2/domain/ 各域文档的聚合、实体、状态机和事件，以及 docs/L2/ARCHITECTURE.md「基础设施与外部依赖」章的存储结论。
3. 读取代码中的实体、schema、迁移和同步事实；更新时同时读取发生变化的集成与部署产物。
4. 扫描源缺失时以已有来源和目标文档为依据，不臆造；跨文档生成顺序归 `align-docs` skill 编排。

## 生成与更新

生成与更新走同一条流程：先读模板，再扫目标位置判断有无既有文档或同定位的旧产物，有则更新、无则新建。

1. 先读 [文档模板](assets/TEMPLATE.md)，按其中标题、编号和层级作为写作基准。
2. 扫描目标位置（`docs/L2/DATA-MODEL.md` 及其所在目录），判断有无既有文档或同定位的旧产物。
3. 无既有产物：以领域模型、存储结论和代码事实填充模板，新建目标文档。
4. 有既有产物：读取旧文档及发生变化的领域、技术、集成、部署和代码事实，保留有来源支撑的有效信息，按模板重建结构，不沿用与模板冲突的旧章节。
5. 重新核对数据模型到数据资产（1:N）、各资产所属存储介质与类型、存储拓扑、锚定关系、数据流转和每个物理数据源的数据构建方式；删除字段级定义和无法追溯来源的表或集合。
6. 数据模型、数据资产、存储选型或锚定关系确有歧义时，询问用户确认。
7. 删除或迁移内容后删净旧节并连续重编号；读取关联文档判断影响，完成联动后逐项执行完成判定。

## 联动

- docs/L2/domain/ 各域文档承载聚合、实体、状态机和事件等业务语义，由 docs-domain skill 维护；本文档只写存储形态与数据流转，并保持领域到存储的映射可追溯。
- 应用划分与存储选型理由归 docs/L2/ARCHITECTURE.md，由 docs-architecture skill 维护；本文档只写存什么和怎么存。
- docs/contracts/outbound/ 集成文档中的外部数据资产、字段术语和数据来源须与本文档一致，集成文档由 outbound-ops
  skill 维护。
- 部署单元与环境参数归 docs/deployment/DEPLOYMENT.md，由 deploy-ops skill 维护；接口契约归
  docs/contracts/inbound/（每应用一份接口 → 代码映射），由
  inbound-ops skill 维护。
- 跨文档编排归 `align-docs` skill。

## 完成判定

- 每个数据模型到其数据资产的映射齐全（1:N），各资产标注存储介质与类型（业务数据 / 技术数据），没有遗漏或混写。
- 存储选型与 docs/L2/ARCHITECTURE.md 的「基础设施与外部依赖」章一致，不重复选型理由。
- 锚定关系只写模型内（靠模型标识），模型间靠引用锚定归 §3 模型关系（ER），两处不重复。
- 每个模型的数据流转图按存储介质分子图，边为领域操作（Action，取自 docs/L2/domain/）而非泛化来源，纯读操作不入图；初始化 /
  迁移写入用 `初始化` 起点节点 + 虚线；图后写明与哪些模型锚定。
- 每个物理存储或数据源都写明存储内容、键模式和数据构建方式，数据构建步骤覆盖适用的初始化、业务写入、同步与清理。
- 两层关系图齐全：§3 以模型为节点画模型间引用（只含业务数据），各模型章以本模型全部资产（业务与技术）为节点、按存储介质分子图画模型内关系；每个模型都要画，只有一个资产时也画出实体。
- 表和集合可追溯到领域聚合或实体，没有孤儿表；图均为可检索文本，D2 图保留图元信息。

## 边界

- 存储选型理由与容量性能预期归 `docs-architecture`，领域业务语义归 `docs/L2/domain/`，日志 / 备份 / 运行产物归
  `deploy-ops`，本 skill 不复制。
