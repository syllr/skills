# docs-structure — 目录结构与文档 ↔ 代码映射

## 定位与管辖文档

本 skill 管辖 L3 事实层的目录结构文档 `docs/L3/STRUCTURE.md`，维护全项目文件组织以及文档与代码的对应关系。L3 是链上事实起点，链序
L1 → L2 → L3，生成与变更沿链各有一个方向：

- 变更时第一个看它：任何改动都先落目录与文件，先确认本文档与实际一致，再由 `align-docs` 沿链向上逐层判定。
- 生成时最后写它：L1 至 L2 的结论都定了才落目录树与映射。
- 修改任何文档前先读它定位对应代码，这一条与方向无关，任何时候都成立。

跨文档编排、目录漂移处理和文档初始化归 `align-docs`
skill。生成或重建目标文档前，先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，按其中章节编号与标题层级写目标文档。

## 读取

- 编辑、新增或重建目标文档前，先读本 skill、[assets/TEMPLATE.md](assets/TEMPLATE.md) 和已有的 `docs/L3/STRUCTURE.md`。
- 直接扫描项目实际目录树，不抽样；同时读取项目宪法、应用架构文档、对外接口文档和业务功能清单。
- 应用架构文档由 `docs-application-architecture` skill 维护，对外接口文档由 `inbound-ops` skill 维护，业务功能清单由
  `docs-business` skill 维护；本 skill 读取并使用这些产物，不复制其内容。
- 读取代码核对目录与文档映射，发现漂移时以代码和实际目录为事实来源。
- 入树前读项目 .gitignore，被忽略的路径与根级通用样板/元文件不入树；目录树使用 ASCII 代码块，文档与注释使用中文；正文只写当前态，不写历史因果。

## 生成流程

1. 先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，再扫描项目完整目录、代码模块、应用划分、接口位置和业务功能位置。
2. 按模板逐节填写真实目录、职责与约束，不套用固定层数或命名风格。
3. 已有目标文档时提取仍有效的项目事实，按模板重建目录树与职责映射，删除过期目录和幽灵目录。
4. 目录与职责定义发生漂移，或需要新增、调整目录时，询问用户确认处理方式。
5. 生成后检查目录映射的完整性、当前态一致性与关联文档状态。

## 更新流程

- 编辑、新增、重建目标文档，或应用划分、接口契约、功能清单变化导致目录增删时进入更新流程。
- 先读目标文档与 [assets/TEMPLATE.md](assets/TEMPLATE.md)，再扫描实际目录和受影响文档；只更新发生变化的内容，保留仍有效的当前态信息。
- 新增或调整目录前与用户确认；目录职责定义与代码不一致时，以代码和实际目录为依据修正文档。
- 章节删除或迁移后同步重编号并清理旧引用，避免文档树出现幽灵目录。
- 更新完成后复核文档与代码映射，并把需要跨文档处理的事项交给 `align-docs` skill。

## 联动

- `docs-application-architecture` 的应用划分或模块归属变化，联动目录树和目录职责。
- `inbound-ops` 的接口位置或契约组织变化，联动接口相关目录映射。
- `docs-business` 的功能清单或待规划能力变化，联动实现目录与文档目录的对应关系。
- 根项目宪法、项目实际目录和其他文档发生变化时，联动本 skill 的当前态记录。
- 跨文档扫描、漂移分诊、目录同步和旧文档迁移由 `align-docs` skill 编排；本 skill 不承担全仓编排。

## 完成判定

格式与结构纪律（正文无加粗与 emoji、无 SSOT 或单一事实源字样、无模板说明与未替换元变量、图为 D2 / Mermaid / ASCII
代码块而无位图、无治理套话与固定元信息、章节编号连续不跳号、相对链接可解析、跨文档章节引用无死链、标题层级与骨架 模板一致、不补写
frontmatter）见根 `AGENTS.md` §2.8，各文档不重复列出；以下为本文档专有判定，全部通过才算完成。

- 目录树与项目实际目录一致，无缺失目录、幽灵目录或未说明的新增目录；不出现被 .gitignore 忽略的路径与根级通用元文件。
- 目录职责表与目录树逐项对应，每个目录都写明用途与约束。
- 文档与代码映射可定位到实际文件和模块，业务待规划能力未被提前落成实现目录。
- 关联的应用架构、接口、业务文档和项目宪法已完成一致性检查。

## 边界

- 只维护 `docs/L3/STRUCTURE.md`，不改业务代码、接口实现、测试文件或其他文档正文。
- 不规定固定目录层数、目录名称或技术框架模板；一切以项目实际分层和代码事实为准。
- 不复制其他文档的业务内容，不写历史与决策原因；跨文档对齐、迁移和初始化由 `align-docs` skill 负责。
- 发现目录与代码冲突时只修正文档映射并报告，不静默改动代码；不自动 commit 或 push。
