# docs-structure — 目录结构与文档 ↔ 代码映射

## 定位与管辖文档

本 skill 管辖 L3 事实层的目录结构文档 `docs/L3/STRUCTURE.md`，维护全项目文件组织以及文档与代码的对应关系。L3 是链上事实起点，链序
L1 → L2 → L3，生成与变更沿链各有一个方向：

- 变更时第一个看它：任何改动都先落目录与文件，先确认本文档与实际一致，再由 `align-docs` 沿链向上逐层判定。
- 生成时最后写它：L1 至 L2 的结论都定了才落目录树与映射。
- 修改任何文档前先读它定位对应代码，这一条与方向无关，任何时候都成立。

跨文档编排和文档初始化归 `align-docs` skill。

- 目标文档结构、各节内容约定与写作规范以 [assets/TEMPLATE.md](assets/TEMPLATE.md) 为准，本 skill
  不另行维护章节骨架或逐节规则；生成或重建目标文档前必须先读取该文件，并严格沿用其中的章节编号、标题层级、结构和生成提示。
- 本 skill 只提供执行方法与跨文档约定，不承载项目具体取值；实例文档只写项目目录事实。
- 目录结构、目录职责与文档 ↔ 代码映射只在本 skill 维护；架构分层与模块划分归 `docs-architecture`，接口位置归 `inbound-ops`
  ，功能清单归 `docs-business`，本 skill 只引用不复制。

## 读取

- 编辑、新增或重建目标文档前，先读本 skill、[assets/TEMPLATE.md](assets/TEMPLATE.md) 和已有的 `docs/L3/STRUCTURE.md`。
- 直接扫描项目实际目录树，不抽样；同时读取项目宪法、架构文档、对外接口文档和业务功能清单。
- 架构文档由 `docs-architecture` skill 维护，对外接口文档由 `inbound-ops` skill 维护，业务功能清单由
  `docs-business` skill 维护；本 skill 读取并使用这些产物，不复制其内容。
- 读取代码核对目录与文档映射，以代码和实际目录为事实来源。
- 入树前读项目 .gitignore，被忽略的路径与根级通用样板/元文件不入树；目录树使用 ASCII 代码块，文档与注释使用中文；正文只写当前态，不写历史因果。

## 生成与更新

生成与更新走同一条流程：先读模板，再扫目标位置判断有无既有文档或同定位的旧产物，有则更新、无则新建。编辑、新增、重建目标文档，或应用划分、接口契约、功能清单变化导致目录增删时都进入本流程。

1. 先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，再扫描目标位置（`docs/L3/STRUCTURE.md`
   及其所在目录）与项目完整目录、代码模块、应用划分、接口位置和业务功能位置。
2. 无既有产物：按模板逐节填写真实目录、职责与约束，不套用固定层数或命名风格。
3. 有既有产物：提取仍有效的项目事实，按模板重建目录树与职责映射，删除过期目录和幽灵目录；只更新发生变化的内容，保留仍有效的当前态信息。
4. 需要新增、调整目录时，询问用户确认处理方式；目录职责定义与代码不一致时，以代码和实际目录为依据修正文档。
5. 章节删除或迁移后同步重编号并清理旧引用，避免文档树出现幽灵目录。
6. 生成后检查目录映射的完整性、当前态一致性与关联文档状态，并把需要跨文档处理的事项交给 `align-docs` skill。

## 联动

- `docs-architecture` 的应用划分或模块归属变化，联动目录树和目录职责。
- `inbound-ops` 的接口位置或契约组织变化，联动接口相关目录映射。
- `docs-business` 的功能清单或待规划能力变化，联动实现目录与文档目录的对应关系。
- 根项目宪法、项目实际目录和其他文档发生变化时，联动本 skill 的当前态记录。
- 跨文档扫描、目录同步和旧文档迁移由 `align-docs` skill 编排；本 skill 不承担全仓编排。

## 完成判定

- 实例文档与 [assets/TEMPLATE.md](assets/TEMPLATE.md) 的章节编号、标题层级和固定结构一致，逐节按各节生成提示核对（文档描述、目录树、目录职责表），且没有模板未定义的内容。
- 目录树与项目实际目录一致，无缺失目录、幽灵目录或未说明的新增目录，且不含被 .gitignore 忽略的路径与根级通用样板 / 元文件。
- 跨节与跨文档一致：目录职责表与目录树逐项对应；文档与代码映射可定位到实际文件和模块；目录与 `docs-architecture` 的应用划分、
  `inbound-ops` 的接口位置、`docs-business` 的功能清单不冲突，业务待规划能力未被提前落成实现目录；关联的架构、接口、业务文档和项目宪法已完成一致性检查。

## 边界

- 新增或调整目录前先与用户确认；发现目录与代码冲突时只修正文档映射并报告，不静默改代码。
