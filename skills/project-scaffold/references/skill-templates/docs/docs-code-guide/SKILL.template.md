# docs-code-guide — 代码规范

## 定位与管辖文档

本 skill 管辖贯穿层代码规范文档 `docs/common/CODE-GUIDE.md`，维护项目实际使用的命名、方法签名、注释和坏味道检查规则。common
本 skill 管辖贯穿层代码规范文档，归档在 common；规则以代码和实际启用的检查为依据，不写理想化规范。

跨文档编排、代码与文档对齐和初始化由 `align-docs` skill
负责。生成或重建目标文档前，先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，按其中章节编号与标题层级写目标文档。

## 读取

- 编辑、新增或重建目标文档前，先读本 skill、[assets/TEMPLATE.md](assets/TEMPLATE.md) 和已有的 `docs/common/CODE-GUIDE.md`。
- 读取项目现有代码风格、实际启用的 lint 或静态检查配置、规则集和既有代码约定。
- 以检查配置和代码事实确定规则与阈值；未启用的检查不写成项目规则，未从配置取得的数值不自行设定。
- 读取项目宪法和关联代码，确认规范适用范围、术语和当前执行入口；跨文档漂移由 `align-docs` skill 处理。
- 文档与注释使用中文；规则正文只写当前状态，不写历史原因。

## 生成流程

1. 先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，再扫描现有代码风格、lint 配置、静态检查配置和规则执行方式。
2. 按模板逐节填写真实规则，命名、方法签名和注释提供正反例，坏味道检查记录实际工具与阈值。
3. 已有目标文档时提取仍有效的规则，按模板重建结构，删除理想化、过期或与配置不一致的内容。
4. 命名风格、阈值或既有约定存在歧义时询问用户；事实明确时自主完成。
5. 生成后检查规则、示例、阈值与实际检查配置的一致性。

## 更新流程

- 编辑、新增、重建目标文档，或 lint、静态检查配置与规则集变化时进入更新流程。
- 先读目标文档与 [assets/TEMPLATE.md](assets/TEMPLATE.md)，再读取变化的配置、规则输出和受影响代码；只更新受影响规则，保留仍有效的当前态内容。
- 配置变更后同步调整规则、阈值、示例和执行入口；已澄清的待澄清项从目标文档删除。
- 规则与代码或检查结果不一致时以实际配置和代码为准修正文档；章节删除或迁移后同步重编号并清理旧引用。
- 更新完成后重新执行完成判定，并交给 `align-docs` skill 做跨文档一致性检查。

## 联动

- `align-docs` skill 负责调用本 skill、处理文档与代码漂移、初始化和迁移，并协调本规范与其它文档的一致性。
- 项目 lint、静态检查或 CI 配置变化时，联动本 skill 更新规则、阈值、示例和执行入口。
- 既有代码约定与实际检查规则冲突时，先记录冲突并以项目实际启用的检查为准；需要用户裁决的命名或阈值歧义交由用户确认。
- 规范只描述当前项目，不复制其它文档内容，不替其它 `docs-*` skill 定义目标文档结构。

## 完成判定

格式与结构纪律（正文无加粗与 emoji、无 SSOT 或单一事实源字样、无模板说明与未替换元变量、图为 D2 / Mermaid / ASCII
代码块而无位图、无治理套话与固定元信息、章节编号连续不跳号、相对链接可解析、跨文档章节引用无死链、标题层级与骨架 模板一致、不补写
frontmatter）见根 `AGENTS.md` §2.8，各文档不重复列出；以下为本文档专有判定，全部通过才算完成。

- 每条规则都能对应到实际启用的 lint 或静态检查，规则与配置、代码现状一致。
- 命名、方法签名和注释均有正反例，示例能够直接对照执行。
- 阈值、工具名称和执行入口取自项目实际配置，未启用或无法确认的规则不写成既定事实。
- 已澄清的待澄清项已删除，正文无占位、填充说明或过期规则。
- 与项目宪法、实际代码和检查配置的关联内容已完成一致性检查。

## 边界

- 只维护 `docs/common/CODE-GUIDE.md`，不修改业务代码、lint 配置、静态检查配置或 CI 配置。
- 不套用理想化命名风格、固定阈值或未启用的工具规则；项目实际配置和代码事实优先。
- 不写历史与决策原因，不复制其它文档内容；跨文档对齐、初始化和迁移由 `align-docs` skill 负责。
- 不自动 commit 或 push，不代替用户裁决未明确的命名风格、阈值或规范冲突。
