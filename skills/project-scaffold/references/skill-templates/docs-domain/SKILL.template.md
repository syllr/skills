# docs-domain — 领域模型文档

## 定位与管辖文档

本 skill 负责 docs/L2/domain/ 下的领域模型总文档 DOMAIN-MODEL.md 与每个业务域的 {域}.md。总文档负责业务域边界与关系、跨聚合服务、契约落地和 Mapper；域文档负责一个业务域内的聚合、约束、领域操作、状态机和领域事件。

生成或更新任何产物前，先读取 [assets/TEMPLATE.md](assets/TEMPLATE.md)，按其中对应产物的骨架写入；本文件不重复目标文档的章节结构。文档体系按 L0 → L1 → L2 → L3 → L4 → common 编排，跨层漂移由 docs-align skill 统一调度。

## 读取

- 读取目标文档及其所在目录中的现有内容，区分总文档与业务域文档，保留仍然有效的事实。
- 读取 L1 的 docs-business 产物（业务流程），核对业务能力及其状态；标记为待规划的能力不进入领域模型。
- 读取领域层代码、公共类型、接口与事件定义，使用 File:Line 作为事实依据；不以推测补齐缺失对象。
- 读取与领域对象相关的应用架构、数据架构和接口信息，识别跨文档关系与下游影响。
- 读取既有文档时只提取有效内容，结构按模板重建；源缺失时明确报告，不臆造。

## 生成流程

1. 判定本次目标是总文档还是单个业务域文档，并读取模板中对应产物的完整骨架。
2. 扫描 L1 业务产物、领域代码、相关架构文档和目标旧文档，建立可追溯的事实清单。
3. 先写总文档的业务域边界与关系，再为每个实际业务域生成独立文档，并把域文档登记到总文档清单。
4. 对每个实体、约束、领域操作、状态、事件与接口核对代码或上游文档；没有来源的概念不写入。
5. 命中 deep-dives 单列条件时，跨模块交互、永久参数、精度分层与坑位四项中命中两项，将细节交由 docs-deep-dives skill 承载，本目录只保留必要摘要。
6. 仅在建模方法、聚合边界或是否单列 deep-dives 存在真实歧义时询问用户。
7. 生成后执行完成判定，并按联动规则同步受影响文档。

## 更新流程

1. 读取旧的总文档、业务域文档、模板和全部输入源，先建立变更清单。
2. 对照代码、L1 产物与关联文档，区分仍有效事实、已删除内容和新增内容。
3. 更新总文档与受影响业务域文档；新增、删除或合并业务域时，同步总文档的域文档清单。
4. 重新核对聚合、领域操作、状态、事件和跨域接口的引用，删除已失效的交叉引用。
5. 重新执行 deep-dives 收敛判断、下游联动和完成判定；发现源冲突时以代码或已确认事实为准并报告。

## 联动

- L1 业务能力、用户故事或能力状态变化时，先更新 docs-business（业务流程），再更新本目录对应产物。
- 领域对象、聚合边界或领域事件变化时，联动 docs-data-architecture 的存储映射和 docs-application-architecture 的模块映射。
- 业务域新增、删除或合并时，同步总文档域文档清单，并通知 docs-align skill 处理跨文档一致性。
- 高复杂度问题命中下沉条件时，由 docs-deep-dives skill 承载详情；本目录保留发现入口所需的摘要，不建立反向引用。
- 待规划能力不得在 docs-inbound、docs-application-architecture、docs-structure、openapi 等实现视图留下内容。
- 跨层扫描、漂移分诊和生成顺序由 docs-align skill 编排，本 skill 只处理本目录产物。

## 完成判定

以下全部通过才算完成：

- 总文档与业务域文档均符合 [assets/TEMPLATE.md](assets/TEMPLATE.md) 中对应产物的结构、标题层级和链接要求。
- 总文档登记的业务域与实际文件一一对应，新增、删除或合并没有漏登记。
- 聚合、实体、值对象、约束、领域操作、状态、事件和接口均能追溯到代码或上游文档。
- 能力状态为待规划的业务域没有对象、操作、状态机、事件或接口残留。
- 领域操作、状态变化、事件和图示相互一致，跨域服务与数据设计没有越界内容。
- 与 docs-business、docs-data-architecture、docs-application-architecture 及 deep-dives 的引用方向和内容一致。
- 文档中的相对链接可解析，实例正文没有生成提示、方法论、治理套话、加粗或 emoji。

## 边界

- 只维护 docs/L2/domain/ 下的总文档和业务域文档；其他文档由对应 docs-* skill 维护，跨文档编排归 docs-align skill。
- 物理存储格式、ER、表清单和领域到存储映射归 docs-data-architecture；应用模块划分归 docs-application-architecture。
- 禁止自创实体、值对象、事件、状态、接口或业务规则；跨聚合只按既有标识引用，接口和对象须能回到代码或上游文档。
- 领域操作只记录本聚合根的操作；跨聚合领域服务在总文档的跨聚合服务位置登记，聚合内保持强一致，跨聚合保持最终一致。
- 审核类多态操作逐态说明状态转移与事件；领域事件使用过去时命名，只记录已发生事实，读取不产生事件。
- 聚合、实体、事件等内容条目按名称标识，规则编号使用 R1、R2 形式。
- 图示格式遵循 docs-align skill 的约定，项目另有约定时按项目约定执行。
- deep-dive 引用本目录，本目录不反向引用 deep-dives；发现入口由 docs-deep-dives 的目录索引承担。
- 跨文档使用相对 Markdown 链接，细节使用 File:Line；不写固定元信息表、单一事实源标签或变更记录，不自动修改业务代码，不自动 commit 或 push。
