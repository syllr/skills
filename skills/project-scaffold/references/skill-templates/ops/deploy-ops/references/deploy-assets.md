# 部署资产声明（deploy-assets）

本文件是 `docs/deployment/` 预期资产的唯一来源：各发布环境有哪些配置、文件命名与旧资产检出都在这里定义。
`DEPLOYMENT.md` §7 是面向人读的逐项说明，不作为资产齐全性的判定依据。

## 1. 环境词表（唯一来源）

环境名以 `DEPLOYMENT.md` §2.1 环境矩阵为准（如 standalone / dev / prod），目录名与 `.env` 文件名一律沿用，不新建命名。

## 2. 预期资产集（唯一来源）

`docs/deployment/` 只需承载各发布环境的配置：

```
docs/deployment/
├── configs/                  # 配置模板（不参与运行），键集基准
│   └── .env.example          # 各环境配置的键集模板
└── <env>/                    # 每环境一目录，环境名 = §2.1
    └── .env.<env>            # 该环境的配置值
```

- 目标机运行时目录、发布产物目录、数据库与中间件的编排副本都不进 `docs/deployment/`：它们是目标机上的运行态或中间件自身资产，
  留在代码库自己的位置，本目录不收。
- 项目的发布、启动、回滚等执行方式（脚本、命令、编排文件）由 `DEPLOYMENT.md` §5.3 按项目实际情况记载；本目录不预置任何脚本，
  已有脚本按 `DEPLOYMENT.md` §7 逐项登记实际路径即可。

## 3. 配置约定

- 键集基准：`configs/.env.example` 声明全部键，永不参与运行。
- 实际取值：各环境 `.env.<env>` 填该环境的值，不回写模板。
- 键集漂移：`configs/.env.example` 与各环境 `.env.<env>` 的键集必须一致，多出的键与缺失的键都要报出来。
- 项目不用 `.env` 形式的环境配置时（如只有一份共享配置、或配置在代码内），按实际形态登记，不为对齐本节硬拆多环境目录。

## 4. 旧资产检出

每次环境变更或对齐时逐项核对磁盘与第 2 节的预期资产集：

- 预期有而磁盘无：某环境目录或 `.env.<env>` 缺失，按 §5 补齐。
- 磁盘有而预期无：旧资产，提示用户确认后删除。判断依据是 `DEPLOYMENT.md` §2.1 环境矩阵与 §3.1 部署单元表里已不存在的环境或单元，
  不因为「`DEPLOYMENT.md` §7 还列着它」而保留。
- 环境删除：`<环境>/` 整目录删除，`DEPLOYMENT.md` §2.1 矩阵行、§4 / §5 对应小节、§7 说明项同步清行。
- 键集漂移：按 §3 报出多出与缺失的键。

## 5. 生成动作

1. 由 `configs/.env.example` 复制出各环境 `<env>/.env.<env>`，值留空由部署机填。

## 6. 维护动作

- 新增环境：建 `<env>/` + `.env.<env>`（复制模板）+ 同步 §1 环境词表 / `DEPLOYMENT.md` §2.1 矩阵 / §3 部署单元（按
  `deploy-ops` skill）。
- 新增变量：改 `configs/.env.example`（键集）+ 各环境 `.env.<env>` 对齐 + 登记 `DEPLOYMENT.md` §7。
- 脚本与流程一致性：改 `DEPLOYMENT.md` §5.3 后同步项目内实际脚本（反之亦然）。

## 7. 纪律

- 环境名一律来自 §1；配置模板是键集基准，真实配置键集与之对齐。
