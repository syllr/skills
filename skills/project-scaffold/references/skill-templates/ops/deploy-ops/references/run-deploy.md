# 部署（执行部署）

## 读取

- 读目标环境 `docs/deployment/<env>/DEPLOYMENT.md` 的 §3.1 应用清单与各应用章（部署知识 SSOT）。

## 步骤

1. 环境确认：列 `docs/deployment/` 下的环境目录，列出可用环境，问用户部署到哪个环境、范围（应用 /
   服务）；并确认本环境的版本标识手段（标识怎么打、打在哪、怎么核对）——版本标识逐环境不同，与用户对齐，不套用其他环境或模板预设。未确认前不执行任何部署动作。
2. commit 询问：问用户「先 commit 再部署」还是「不 commit 直接部署当前代码」；选先 commit 时，须用户显式授权后才执行 commit；选不
   commit 直接部署时，版本标识核对中「本地代码与目标机版本标识」不一致属预期，报告中如实说明。
3. 执行：按目标环境 `DEPLOYMENT.md` 对应章节执行（部署走该应用章，环境名取目录名），AI 不手拼部署命令；回滚按该应用章
   记载的项目既有方式。
4. 产物清理：项目若约定历史产物保留期，到期向用户报告并询问是否清理（不自行删）。
5. 报告：版本标识核对（按本环境采用的标识手段，如提交号 / 包摘要 / 时间戳 / ETag）、该应用章 `## 部署` 记载的健康检查方式与结果、失败项（如有）。

完成判据：部署环境与版本标识手段已经用户确认；按该应用章（或全量部署章）执行，未手拼命令；报告含版本标识核对（按本环境手段，已与用户确认）、
`## 部署` 记载的健康检查结果、失败项如实列出。

## 联动

- 测试期访问系统与工具调用经 `tools-ops` skill。

## 边界

- `commit` 须用户显式授权；部署期健康检查与冒烟验证属「系统访问唯一入口」的部署期豁免，由本 skill 执行。
