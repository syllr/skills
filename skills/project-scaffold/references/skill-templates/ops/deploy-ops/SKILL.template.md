# deploy-ops — L3 部署域（说明书 + 部署资产 + 部署执行）

## 定位与管辖文档

本 skill 是 L3 部署域的唯一入口，同时管辖三类产物：

| 产物       | 路径                             | 性质 | 事实来源                                 |
|------------|----------------------------------|------|------------------------------------------|
| 部署说明书 | `docs/deployment/DEPLOYMENT.md`  | 文档 | 项目事实（应用划分 / 技术栈 / 资产现状） |
| 部署资产   | `docs/deployment/`               | 资产 | 本 skill 生成与维护                      |
| 部署执行   | 按项目既有流程发布 / 启动 / 回滚 | 动作 | `DEPLOYMENT.md` §4 与 §5.3               |

部署知识的 SSOT 是 `DEPLOYMENT.md`（环境矩阵 §2.1 / 各环境启动 §4 / 各环境发布流程 §5.3 / 密钥 §6 / 资产逐项说明
§7），执行时现场读文档照做，本 skill 不复制任何命令与环境信息。资产的预期集 SSOT 是
[deploy-assets.md](references/deploy-assets.md) §2，`DEPLOYMENT.md` §7 只是人类可读说明。

跨文档编排、生成顺序与漂移处理归 `align-docs` skill；测试期访问系统经 `tools-ops` skill，部署期的健康检查与冒烟验证属于「系统访问唯一入口」的部署期豁免，由本
skill 执行。

本 skill 自带资料：

- 产物骨架 [assets/TEMPLATE.md](assets/TEMPLATE.md)——`DEPLOYMENT.md` 的目标结构
- 资产与多环境约定 [references/deploy-assets.md](references/deploy-assets.md)——各发布环境有哪些配置、环境命名约定、键集基准与新增环境步骤

## 读取

- 编辑、重建说明书或生成资产前，先读本 skill 与 [assets/TEMPLATE.md](assets/TEMPLATE.md)，再列 `docs/deployment/`
  的实际目录树。
- 读取应用架构（`docs-application-architecture`）定位部署单元、技术架构（`docs-technology-architecture`）定位运行时与存储方式。
- 读取接口契约（`inbound-ops`）与外部集成（`outbound-ops`）确认上线入口、外部服务、密钥与回调。
- 读取目标文档、项目宪法和关联代码或配置，区分已落盘事实、待确认事项与部署资产现状。
- 执行部署前读 `DEPLOYMENT.md` §2.1 环境矩阵、§4 与 §5 中目标环境的小节、§6 密钥、§7 资产说明。
- 文档按 L1 → L2 → L3 生成，生成下层文档前先读上层产物；跨文档顺序与漂移清账由 `align-docs` skill 编排。
- 图使用 D2、Mermaid 或 ASCII 代码块直接写入 Markdown；容器式分层图遵循 `c4-container-diagram` skill，D2
  图保留图名、视角、用途与边界等自描述信息，正文和注释使用中文。

## 生成与更新

生成与更新走同一条流程：先读模板，再扫目标位置判断有无既有文档或同定位的旧产物，有则更新、无则新建。

1. 先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，按其中章节作为写作基准；列 `docs/deployment/` 的实际目录树，判断有无既有
   `DEPLOYMENT.md`、既有资产或同定位旧产物。
2. 无既有说明书：依据应用划分、技术栈、接口契约和部署资产现状逐节填写真实内容，没有事实依据的值不臆造。
3. 有既有说明书：读发生变化的关联文档和资产，提取仍有效的业务值，按模板重建章节、表格、图和命令，删除过期结构与旧图，保留仍有效的当前态信息。
4. 部署资产（首次落地）：读源 `DEPLOYMENT.md` §2.1 环境矩阵（环境清单）+ §5.3
   发布流程 + [deploy-assets.md](references/deploy-assets.md) §2（资产结构 SSOT）；逐环境建 `<env>/`
   及其配置，键集取自项目配置模板，每个环境有哪些项、命名怎么定按 [references/deploy-assets.md](references/deploy-assets.md)
   §2；发布脚本、编排与回滚等执行件沿用项目既有方式，不新建、不套用模板，项目已有就逐项登记、没有就按 §5.3 登记清楚。
5. 资产更新：新增环境按 [references/deploy-assets.md](references/deploy-assets.md) §2 补该环境的配置，同步 `DEPLOYMENT.md`
   §2.1 环境矩阵 / §3.1 部署单元；改发布流程先改 §5.3（接口 SSOT）再改脚本实现匹配，两者必须一致；改配置先改配置模板（键集
   SSOT）再改各环境配置，键集保持一致。
6. 回写登记：把新增或变更的资产按「说明书」的写法重建 `DEPLOYMENT.md` §7（路径 / 归属 / 生效机制）；章节删除或迁移后同步重编号并清理旧引用。
7. 写入后删除模板中的 HTML 生成提示注释；部署形态随项目实际情况（容器编排或裸进程皆可），不套用模板预设的流程。
8. 发现说明书与代码或配置不一致时，以实际代码和配置为准修正说明书；数据库迁移按项目实际工具执行：已应用 revision
   不再改，发布前先在本地自测，迁移失败即中断。
9. 报告生成或变更清单 + `.env` 待补项；部署形态或版本标识机制存在歧义时询问用户，其余无歧义事项自主完成；应用增减、技术栈变化、接口与密钥变化等跨
   skill 同步见「联动」，跨文档生成顺序、漂移扫描与一致性清账交 `align-docs` skill。

## 执行

执行分诊（进入执行的第一件事）：

| 分诊       | 触发                                         | 动作     |
|------------|----------------------------------------------|----------|
| 1 执行部署 | 部署 / 发布 / 启动指定环境 / 回滚 / 部署状态 | 执行部署 |
| 2 生成资产 | 首次落地部署资产，或某环境配置缺失           | 生成资产 |
| 3 维护资产 | 新增环境 / 改发布流程 / 改配置 / 同步键集    | 维护资产 |

### 执行部署

1. 环境确认：读 `DEPLOYMENT.md` §2.1 环境矩阵，列出可用环境，问用户部署到哪个环境、范围（应用 / 服务）——未确认前不执行任何部署动作。
2. commit 询问：问用户「先 commit 再部署」还是「不 commit 直接部署当前代码」；选先 commit 时，须用户显式授权后才执行 commit；选不
   commit 直接部署时，版本核对中 `BUILD_COMMIT` 与本地 HEAD 不一致属预期，报告中如实说明。
3. 执行：按 `DEPLOYMENT.md` 对应章节执行（发布走 §5.3，启动走 §4，环境名取 §2.1），AI 不手拼部署命令；回滚按 §5.3 记载的项目既有方式。
4. 产物清理：项目若约定历史产物保留期，到期向用户报告并询问是否清理（不自行删）。
5. 报告：版本核对（`BUILD_COMMIT` 与本地 HEAD 对比）、`DEPLOYMENT.md` §3.1 记载的健康检查方式与结果、失败项（如有）。

## 联动

- 应用增减或应用边界变化时，联动部署单元、环境说明与部署参数，读取 `docs-application-architecture`。
- 技术栈、运行时或存储方式变化时，联动部署方式与运行形态，读取 `docs-technology-architecture`。
- 接口上线、外部服务、密钥或回调变化时，联动部署配置与验证入口，读取 `inbound-ops` 与 `outbound-ops`。
- 测试期访问系统与工具调用经 `tools-ops` skill；跨文档生成顺序、漂移扫描与一致性清账交 `align-docs` skill。

## 完成判定

格式与结构纪律（正文无加粗与 emoji、无 SSOT 或单一事实源字样、无模板说明与未替换元变量、图为 D2 / Mermaid / ASCII
代码块而无位图、无治理套话与固定元信息、章节编号连续不跳号、相对链接可解析、跨文档章节引用无死链、标题层级与骨架模板一致、不补写
frontmatter）见根 `AGENTS.md` §2.8，各文档不重复列出；以下为本文档专有判定，全部通过才算完成。

- 说明书与 `docs/deployment/` 资产同 [deploy-assets.md](references/deploy-assets.md) §2 的预期资产集逐项对应：无缺失项，无预期外残留。
- `DEPLOYMENT.md` §2.1 环境矩阵与各环境配置一一对应，键集与配置模板一致，无未登记的环境。
- §5.3 发布流程与脚本实现一致，§7 资产登记覆盖实际资产路径与生效机制。
- 执行部署时报告包含版本核对（`BUILD_COMMIT` 与本地 HEAD）与健康检查结果，失败项如实列出。
- 正文只写项目事实，不套用模板预设；发现与代码或配置冲突时以实际代码与配置为准修正。

## 边界

- 部署知识的 SSOT 是 `DEPLOYMENT.md`，本 skill 不复制命令与环境信息；执行时现场读文档照做。
- 只维护 `docs/deployment/DEPLOYMENT.md` 与 `docs/deployment/` 资产；部署单元、环境与密钥以项目实际为准。
- 发布脚本、编排与回滚等执行件沿用项目既有方式，不新建、不套用模板；没有时按 §5.3 登记清楚。
- 数据库迁移按项目实际工具执行，已应用 revision 不再改；跨文档编排、漂移处置归 `align-docs` skill。
- 不自动 commit 或 push；commit 须用户显式授权。
