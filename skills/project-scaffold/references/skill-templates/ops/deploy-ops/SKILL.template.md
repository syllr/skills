# deploy-ops — L3 部署域

本 skill 是 L3 部署域唯一入口：一进来先看「分诊」，再进入对应章节。部署知识的 SSOT 是各环境 `DEPLOYMENT.md`，执行时现场读目标环境文档照做，本
skill 不复制任何命令与环境信息。

- 每个发布环境一个目录 `docs/deployment/<env>/`，内含说明书 `DEPLOYMENT.md` 与配置 `.env.<env>`；说明书按应用为中心组织（§3.1
  应用清单，每个应用一章含其部署与配置密钥与资产与运行产物；末尾是全量部署与种子凭据）。
- 环境名 = 目录名 = `.env.<env>` 后缀，一律相同；只装发布环境，开发流程（本机 standalone）不是发布环境、不进此目录，其说明与纪律归项目本机
  rule。
- 不设跨环境共享配置目录：键集以各环境 `.env.<env>` 彼此一致为准；脚本不进 `docs/deployment/`，登记在各环境 `DEPLOYMENT.md`
  各应用章的「资产」节。
- 运行产物（日志 / 备份 / 模型权重缓存 / 临时产物）归各应用章的「运行产物」节；业务数据模型归 `docs/L2/DATA-MODEL.md`，两者不重复。

## §1 部署（执行部署）

### 读取

- 读目标环境 `docs/deployment/<env>/DEPLOYMENT.md` 的 §3.1 应用清单与各应用章（部署知识 SSOT）。

### 步骤

1. 环境确认：列 `docs/deployment/` 下的环境目录，列出可用环境，问用户部署到哪个环境、范围（应用 /
   服务）；并确认本环境的版本标识手段（标识怎么打、打在哪、怎么核对）——版本标识逐环境不同，与用户对齐，不套用其他环境或模板预设。未确认前不执行任何部署动作。
2. commit 询问：问用户「先 commit 再部署」还是「不 commit 直接部署当前代码」；选先 commit 时，须用户显式授权后才执行 commit；选不
   commit 直接部署时，版本标识核对中「本地代码与目标机版本标识」不一致属预期，报告中如实说明。
3. 执行：按目标环境 `DEPLOYMENT.md` 对应章节执行（部署走该应用章，环境名取目录名），AI 不手拼部署命令；回滚按该应用章
   记载的项目既有方式。
4. 产物清理：项目若约定历史产物保留期，到期向用户报告并询问是否清理（不自行删）。
5. 报告：版本标识核对（按本环境采用的标识手段，如提交号 / 包摘要 / 时间戳 / ETag）、该应用章 `## 部署` 记载的健康检查方式与结果、失败项（如有）。

完成判据：部署环境与版本标识手段已经用户确认；按该应用章（或全量部署章）执行，未手拼命令；报告含版本标识核对（按本环境手段，已与用户确认）、
`## 部署` 记载的健康检查结果、失败项如实列出。

### 联动

- 测试期访问系统与工具调用经 `tools-ops` skill。

### 边界

- `commit` 须用户显式授权；部署期健康检查与冒烟验证属「系统访问唯一入口」的部署期豁免，由本 skill 执行。

## §2 资产（部署说明书 + 部署资产）

### 读取

- 读本 skill 与 [assets/TEMPLATE.md](assets/TEMPLATE.md)（各环境 `DEPLOYMENT.md` 目标结构）；列 `docs/deployment/`
  实际目录树，判断各环境目录里有无既有 `DEPLOYMENT.md` 与配置。
- 读架构（`docs-architecture`）定位部署单元、运行时与存储方式。

### 步骤

资产集（本 skill 的 SSOT）：每环境一目录 `docs/deployment/<env>/`，含 `DEPLOYMENT.md`（说明书，按 TEMPLATE）与 `.env.<env>`
（该环境配置值）；磁盘有而预期无的即旧资产（如遗留共享配置目录或旧脚本），确认后删。按情况走：首次落地 → 生成；新增环境 /
改流程 / 改配置 → 维护。

#### 生成（首次落地）

1. 读 [assets/TEMPLATE.md](assets/TEMPLATE.md) 作写作基准；列 `docs/deployment/` 实际目录树，判断各环境目录里有无既有
   `DEPLOYMENT.md` 与配置。
2. 每环境建 `<env>/`，写 `<env>/.env.<env>`（键集与其他环境一致，值留空由部署机填）；按 TEMPLATE 写 `<env>/DEPLOYMENT.md`。
3. 有既有说明书：读发生变化的关联文档和资产，提取仍有效的业务值，按模板重建章节、表格、图和命令，删除过期结构与旧图，保留仍有效的当前态信息。
4. 无既有说明书：依据应用划分、技术栈、接口契约和部署资产现状逐节填写真实内容；项目的发布 / 启动 /
   回滚等执行件沿用既有方式，不新建、不套用模板，已有就逐项登记在各应用章「资产」节。
5. 数据库迁移按项目实际工具执行：已应用 revision 不再改，发布前先在本地自测，迁移失败即中断。

正文只写项目事实，没有事实依据的值不臆造，不套用模板预设；发现说明书与代码或配置不一致时，以实际代码和配置为准修正说明书。

#### 维护（新增环境 / 改流程 / 改配置）

1. 新增环境：建 `<env>/` + `.env.<env>`（键集对齐其他环境）+ `<env>/DEPLOYMENT.md`（按模板），同步该环境说明书 §3.1 应用清单与部署单元。
2. 改部署流程：先改对应应用章（接口 SSOT）再改脚本实现匹配，两者必须一致。
3. 改配置：各环境 `.env.<env>` 同步对齐，键集保持一致；新增变量时同时改全部环境。
4. 回写登记：把新增或变更的资产按「说明书」的写法重建该应用章的「资产」节（路径 / 生效机制 / 用途）；章节删除或迁移后同步重编号并清理旧引用。
5. 逐环境考虑：改动某发布环境后，评估其他发布环境是否同样需要（配置键、脚本、流程、运行产物结构等），需要则同步，避免环境间漂移。
6. 报告生成或变更清单 + `.env` 待补项；部署形态或版本标识机制存在歧义时询问用户，其余无歧义事项自主完成。

完成判据：每个环境目录与预期资产集逐项对应（都有 `DEPLOYMENT.md` 与 `.env.<env>`
），无缺失项、无预期外残留；各环境键集彼此一致、无未登记的环境与键集漂移；新增 /
变更资产已回写对应应用章；各应用章的部署流程与脚本实现一致、资产覆盖实际资产路径与生效机制；各应用章「运行产物」逐项登记路径 /
归属 / 产生方式 / 保留与清理 / 是否进版本库，与 DATA-MODEL 的业务数据模型不重复；正文只写项目事实，不套用模板预设。

### 联动

- 应用增减、应用边界或技术栈、运行时、存储方式变化时，联动部署单元、环境说明与部署参数，读取 `docs-architecture`。
- 接口上线、外部服务、密钥或回调变化时，读取 `inbound-ops` 与 `outbound-ops`。
- 跨文档生成顺序交 `align-docs` skill。

### 边界

- 发布、启动、回滚等执行脚本按环境各自独立（每环境一套，不跨环境共享，允许重复），沿用项目既有方式，不新建、不套用模板。
- 数据库迁移按项目实际工具执行，已应用 revision 不再改；`commit` 须用户显式授权。
