# 测试资产声明

本文件定义 `docs/test/` 的资产布局：目录结构、文件命名与落盘规则。用例卡的 **内容**
规范（结构、写卡硬性要求、机检口径）另见 [case-writing.md](case-writing.md)；本文件只管「放在哪、怎么命名、旧的怎么清」。

## 1. 资产布局

```
docs/test/
├── test-cases/                  正式用例卡，AI 执行器的直接输入
│   ├── api/<领域实体>/            API 卡，按 domain 实体名分组
│   └── flow/<用户故事场景>/       FLOW 卡，按用户故事场景名分组
└── test-records/                执行台账：一次执行一份
    └── <YYYYMMDD-HHmmss>-<归属对象>.md
```

| 路径                                  | 作用                                                                 |
|---------------------------------------|----------------------------------------------------------------------|
| `test-cases/api/<领域实体>/`          | 该领域实体的 API 卡；目录名 = domain 文档里的实体名（kebab）         |
| `test-cases/flow/<用户故事场景>/`     | 该用户故事场景的 FLOW 卡；目录名 = `BUSINESS.md` 里的场景名（kebab） |
| `test-records/<时间戳>-<归属对象>.md` | 一次执行的台账；归属对象 = 被执行的用例或场景                        |

- 两个目录都是 `docs/test/` 的直接子目录，不再往下分层（分组只在 `test-cases/` 下分 `api/` 与 `flow/` 一层）。
- 目录名与文件名一律 kebab-case；时间戳格式 `YYYYMMDD-HHmmss`。
- 层级不再增长：一个实体的 API 卡多了就同目录加文件，不分子目录；场景同理。
- 用例库是增量累积的：只有用户显式指定的场景 / 用例才落卡，没有「应当包含哪些用例」的清单，不做缺失补全。

## 2. 落盘规则

- 用例卡只能经本 skill 落盘，且新增 / 删除由用户显式指定；AI 不得自行创建或删除。
- 一个场景（或一个接口 / 一个用例）一张卡、逐个新增：用户指定目标场景 / 实体后，只读该目标相关的段落、只写这一张卡；不扫用例库批量生成。
- 卡模板 `assets/case-templates/{api-case.md,flow-case.md}` 是骨架来源，复制后替换实体/接口/Case 内容。
- `test-records/` 的时间戳取写入那一刻，归属对象写被执行的用例或场景名。
- 用例执行所需的系统访问只走 `tools-ops` skill，本目录不存连接参数。

## 3. 旧资产清理

实体或场景已从上游文档删除时，清理其残留用例目录：

- `test-cases/api/<实体>/` 对应实体已从 `docs/L2/domain/` 删除：整个目录删除，同时全仓（含 domain 文档）清掉反向引用。
- `test-cases/flow/<场景>/` 对应场景已从 `docs/L1/BUSINESS.md` 删除：同上。
- 命名不合规：目录名与 domain 实体名/用户故事场景名不一致、文件名未用 kebab-case 或时间戳格式，一律视为待修正，交用户确认后重命名并同步引用。
- 台账只增不删：历史 `test-records/` 不因用例删除而清理。

## 4. 门禁

- 每张卡为「头 + Case N（五段：前置条件 / 执行流程 / 期望结果 / 数据对账 / 数据清理）」结构，五段齐全。
- 卡内无占位参数描述，无指向已删文档的 § 引用。
- 卡文件在对应实体/场景目录，目录名与 domain 实体或用户故事场景一致。
- 造数据的 Case 含三态清理。
- 全部命令走 `tools-ops` skill 的工具通道，不写 curl、不裸 SQL。
- 断言三源可回溯：状态码、响应字段、错误码以接口代码为准（经 `inbound-ops` 的接口 → 代码映射定位），实测校准。
- 已删除的实体 / 场景无残留用例目录。
