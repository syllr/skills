# Inbound 契约资产声明

本文件是 `docs/contracts/openapi/` 预期资产的唯一来源：目录结构、每个文件的作用、落盘规则与旧资产检出都在这里定义。
`INBOUND.md` 是面向人读的说明书，只写导出命令、维护规范、CI 防漂移 pipeline、协议支持表与端点计数字段；它不声明资产结构，
也不作为本 skill 判定资产是否齐全的依据。

## 1. 预期资产集

`docs/contracts/openapi/` 由导出与拆分两个动作生成，产物分三层：

| 路径                   | 作用                                                                                                     | 必否         |
|------------------------|----------------------------------------------------------------------------------------------------------|--------------|
| `openapi.yaml`         | 主契约；承载元信息（`info` / `servers` / `security` / `tags`），端点与数据结构全部以 `$ref` 指向拆分文件 | 必           |
| `paths/{域}.yaml`      | 按业务域拆分的端点定义；文件头注释块记录来源、边界与该域 `x-action` 汇总                                 | 必，至少一个 |
| `components/{域}.yaml` | 该域的数据结构定义（schemas / responses / securitySchemes 按 OpenAPI 段落分组在同一文件内）              | 必，至少一个 |

- 目录层级固定为 `openapi.yaml` + `paths/` + `components/` 三层，不新增第四层。
- 域文件名用 kebab-case，与代码中的业务域标识一一对应；域的增删由代码导出结果决定，不手工建文件。
- 拆分口径（全量收敛 `components/`、`paths/` 文件零本地 components）见
  [export-mechanics.md](export-mechanics.md) §2。

## 2. 落盘规则

- 全部文件由 `export_openapi.py` 与 `split_openapi.py` 生成，禁手工编辑；改契约改代码后重新导出。
- 单文件模式（`--format` 单文件且不拆分）下只允许 `openapi.yaml` 一个文件；一旦拆分，`paths/` 与 `components/` 必须同时存在。
- 相对 `$ref` 只能在 `openapi.yaml` → `paths/` → `components/` 这条链上，不允许反向或跨层跳。

## 3. 旧资产检出

每次导出或对齐时逐项核对磁盘与第 1 节的预期资产集：

- 预期有而磁盘无：导出失败或拆分未完成，补跑导出与拆分。
- 磁盘有而预期无：旧资产，提示用户确认后删除——判断依据是代码里已不存在的域（代码导出结果中没有该域）， 不因为「说明书还提到它」而保留。
- 已删除的域：其 `paths/{域}.yaml` 与 `components/{域}.yaml` 必须同时从磁盘移除，不留孤儿文件。
- 校验残留：悬空 `$ref`、指向已删域的引用、未被任何 `paths/` 引用的 `components/{域}.yaml` 均视为残留，须清理。

## 4. 门禁

- 导出命令在说明书与实际执行环境中都能跑通，任一侧失效即视为未完成。
- 重新导出后产物与代码无差异（幂等）。
- 端点计数三方一致：`INBOUND.md` §1 的计数字段 = `paths/` 各文件头汇总 = 导出结果。
