# 维护：页面调用型工具（webmcp）

调 `webmcp` 触达 **前端页面**。核心是 **可用性绑定页面**：每个子工具只在 **它所属页面加载完成后**才真的能跑——先 `goto`
到该页、等加载完成，再调。注册只解决两件事（ **防重名** / 让 agent 发现），不改变可用性。

- 类文档 `docs/tools/tools/webmcp/webmcp.md` 只有两张随项目变的表：环境参数（host）、子工具（工具 ↔ 可用页面）。
- 本工具（`tools/webmcp/webmcp.mjs`）是模板冻结件： **骨架 [assets/tool-webmcp.mjs](assets/tool-webmcp.mjs)（+
  共享 [assets/_util.mjs](assets/_util.mjs)）可整份复制**；首次落地一次，之后不随子工具变——子工具都在页面代码里。

## 读取

- 工程页面代码里的 WebMCP 注册（每页一文件 + 注册层）与页面组件，盘点 **工具 ↔ 可用页面**（工具依赖的能力在哪个页面/组件活着）。
- 现有 `docs/tools/tools/webmcp/`（若有）与该类 `webmcp.md`（环境参数 / 子工具可用页面）。

## 步骤

1. 在 **该能力所在的页面 / 模块**的注册文件里加一个工具对象：
    - `name`：小写下划线（防重名）、全局唯一；
    - `description`： **定义 + 何时用 + 返回 + 失败 + 注意**；
    - `inputSchema`：每参 `description` / `required` / `enum`；
    - `execute`： **返回可 JSON 序列化对象、业务失败不 throw**，复用该页 / 服务层的既有能力。
      能力在动态组件里就用该页 / 组件的 ctx—— **不把它提到全局，也不为埋点改业务结构**。
2. 加进该文件的工具集，挂上注册（同类多工具就照抄该节的结构）。
3. 注册 **只保证防重名**：全局一次（启动时 + 模块级幂等表）或页面挂载注册（卸载注销）——两者都行，不影响可用性。
4. 登记类文档： **依据页面代码**更新 `webmcp.md` 的「子工具（工具 ↔ 可用页面）」——按页面列该页可用的工具（工具 /
   说明），全局可用的单列一节； **生成时不调工具**（页面可能还没发布）。子工具入参不抄（执行时 `--list --path <页>` 取）。
5. 发布后验证：`--list --path <各页>` 能列出该页可用工具；`--seq`（含跨页 `{goto}` + 等加载完成）能实际跑通。

## 完成判据

- 类文档的「子工具」与 **页面代码**一致（发布后可再用各页 `--list --path` 复核）；`--seq` 能 **实际跑通**
  （先到可用页面、等加载完成）；符合统一契约。

## 边界

- 统一契约（stdout / 退出码 / 不默认 / fail-fast / 写授权 / `--help`）见 [contract.md](contract.md)。
- 环境清单 / 连接参数变化时，对齐该类 `webmcp.md` 的环境参数表（Standalone 恒在最前；只改该类文档，不改 `DEPLOYMENT.md`
  本体——那按 deploy-ops）。
- **可用性以能跑为准**：页面未就绪时 `execute` 明确失败（`not_ready` / `not_on_page`），不假装可用；能注册但跑不了 = 不可用，不算。
- 不把子工具的入参摊成本工具的「工具参数」——那是页面代码的事，本工具只做通用调度。
- 默认只读（webmcp 无写开关）；唯一入口 / 禁旁路见「分诊」；目标无可用工具 → 走「工具集新增 / 删除 / 更新」流程。
- 页面 / WebMCP 通道不存在时，本类不落地，`webmcp.md` 保留并写「本类未落地」。
