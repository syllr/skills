# 调用：数据 / 中间件直连型工具

直连基础设施取数 / 查询（DB / Redis / Kafka / ES / 对象存储 / 向量库等）。项目相关的只有一张表（环境参数），在
`docs/tools/tools/middleware/middleware.md`。

- 用途：直连基础设施取数 / 查询。
- 注意：默认只读，写加 `--write` 且须先得到用户授权；参数一律不给默认值。

## 读取

- 该类 `docs/tools/tools/middleware/middleware.md`——本项目只有环境参数表。
- `docs/deployment/`（连接参数取值）。
- 单工具用法：`--help`。

## 步骤

1. 选环境：按类文档「环境参数」表选中该环境那一行。
2. 选工具：按类文档选该中间件对应的工具（一个中间件一个工具，如 `<工具>`）。
3. 调：把该行连接参数 + 只读命令 / 查询拼进命令（见下「调用方式」）。
4. 报告：结论 + 所用环境 + 原始证据（stdout 单行 JSON），按退出码判断失败类型。

完成判据：参数取自类文档的环境参数表行；读 stdout 单行 JSON 并核对退出码；断言由 AI 判断、工具只取证据。

## 工具参数（固定）

- 位置参数＝该中间件的命令 / 查询（最典型的工具参数）；连接参数按「环境参数」表该行拼装。
- 一律不给默认值，缺任一必填项即报错（退出码 2）；完整语义以 `--help` 为准。

## 退出码（固定）

| 码 | 含义                                           |
|----|------------------------------------------------|
| 0  | 成功                                           |
| 1  | 操作被拒（未加 `--write` 的写 / 不放行的操作） |
| 2  | 参数错误                                       |
| 3  | 网络失败                                       |
| 4  | 数据层失败                                     |
| 5  | 配置错误                                       |

- 输出契约：stdout 只输出一行 JSON，人类诊断信息走 stderr。

## 调用方式

```bash
# 只读
npm run <工具> -- "<只读命令 / 查询>" <环境参数表该行>

# 写（须先得到用户授权）
npm run <工具> -- --write "<写命令 / 查询>" <环境参数表该行>
```

## 边界

- 默认只读，写加 `--write` 且须先得到用户授权；唯一入口 / 禁旁路见「分诊」；目标无可用工具 → 走「工具集新增 / 删除 / 更新」流程（骨架
  `assets/tool-middleware.mjs`）。
