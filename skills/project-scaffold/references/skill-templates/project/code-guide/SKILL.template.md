# code-guide — 子项目 AGENTS.md

## 定位与管辖文档

本 skill 为子项目目录生成 / 维护一份 `AGENTS.md`，写清该子项目的概览、代码地图、约定与红线，供 AI
在该子目录下工作时自动读取。产物落在各子项目自己的目录下，不写 `docs/`。

- 新增：由用户指定一个子目录（或该目录下的 `AGENTS.md`），本 skill 只聚焦这个目录，不自己扫全项目找应用。
- 更新：扫描项目内已有的子项目 `AGENTS.md`（根 `AGENTS.md` 除外），逐个更新。
- 根目录不算子项目：根 `AGENTS.md` 是项目宪法（归 project-scaffold）。
- 每个目录的规范不同，每份 AGENTS.md 只写该目录自身的约定。
- 目标产物结构以 [assets/AGENTS.template.md](assets/AGENTS.template.md) 为准，本 skill 不另行维护章节骨架。
- 生成内容用 `<!-- code-guide:begin -->` 与 `<!-- code-guide:end -->` 包裹，标明由本 skill 生成；标记之外是用户自行维护的内容，本
  skill 一律不动。
- 分流：用户要写的内容属于模板章节（概览 / 代码地图 / 约定 / 红线）就按模板写进标记块；不属于模板覆盖的内容则留在标记外，交用户自行维护。

## 读取

- 新增：读用户指定的子目录（或该目录下的 `AGENTS.md`），聚焦该目录的代码、配置与既有约定（lint / 静态检查 / 构建 / 测试配置）。
- 更新：扫描项目，列出所有子项目 `AGENTS.md`（根 `AGENTS.md` 除外），逐一读其所在目录的代码、配置与既有约定。
- 写「概览」前对照 `docs/L2/ARCHITECTURE.md` 的应用划分，确认本目录对应哪个 / 哪些应用——可能是一个应用、某应用的一个组件，或跨应用的复杂组件。
- 两种情况都先读 [assets/AGENTS.template.md](assets/AGENTS.template.md)，确认章节与字段。

## 生成与更新

1. 判断归属：用户要写的内容属于模板章节（概览 / 代码地图 / 约定 / 红线）则按模板写进 `code-guide`
   标记块；不属于模板覆盖的内容则留在标记外，交用户自行维护，本 skill 不写。
2. 先读 [assets/AGENTS.template.md](assets/AGENTS.template.md)，确认章节与字段。
3. 新增：用户指定目录后，为 `<该目录>/AGENTS.md` 生成内容；未指定目录时不新建。
4. 更新：对每个既有子 `AGENTS.md`，只替换 / 更新 `code-guide` 标记内的内容，标记之外原样保留；既有文件没有该标记时，不覆写，在文件顶部插入标记块，下方用户内容保留。
5. 只写当前态：不写因果链、不留「已废弃 / 已迁移」占位；技术栈、版本、命令与阈值一律取自实际配置与代码，不写理想化规则。
6. 复读并核对每份 AGENTS.md 的标记块与模板一致、标记外内容未被改动，报告产物清单。

## 联动

- 根 `AGENTS.md` 是项目宪法，由 project-scaffold 生成与维护，本 skill 不改；本 skill 只写各子项目目录下的 AGENTS.md。

## 完成判定

- 新增时目标目录下的 AGENTS.md 已生成；更新时项目内每个子项目 AGENTS.md 都已更新。
- 每份 AGENTS.md 结构符合 [assets/AGENTS.template.md](assets/AGENTS.template.md)，覆盖概览 / 代码地图（目录树 +
  文件→作用 + 任务→对应文件）/ 约定 /
  红线；「约定」用表格按类别逐行列出实际启用的规则（类别参考模板的「常用类别」），未涉及的不写。
- 生成内容都在 `code-guide` 标记之内；标记之外的用户内容未被改动。
- 概览、技术栈、版本、命令与阈值取自实际配置与代码，无凭空补造；约定只写该目录实际启用的规则，不写理想化规则。
- 无因果链与占位；正文只表现当前态。

## 边界

- 只写各子项目目录下的 `AGENTS.md`，不写 `docs/`、不改根 `AGENTS.md`、不改业务代码。
- 新增只处理用户指定的目录，不自动扫全项目找应用；更新只处理既有子 `AGENTS.md`。
- 只改 `code-guide` 标记内；标记之外的用户内容一律不动。
- 只把模板覆盖的内容写进标记块；模板不覆盖的内容不写进标记块，留标记外由用户自行维护。
- 不重复全局文档内容（目录总览、架构、领域模型等），只写该目录自身的约定。
- 代码规范以项目实际启用的 lint / 静态检查为准；未启用的检查不写成规则。
