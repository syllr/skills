# docs-deployment — 部署说明书与部署资产登记

## 定位与管辖文档

本 skill 管辖 `docs/L4/DEPLOYMENT.md` 以及 `docs/L4/deployment/` 的部署资产登记。目标文档回答如何部署上线与如何运维；部署资产本体保留在运行位置，本 skill 只维护说明书中的登记信息。

部署执行、部署脚本、compose 与多环境 `.env` 的生成和维护归 `deploy-ops` skill；跨文档编排、生成顺序与漂移处理归 `docs-align` skill。生成或重建目标文档前，先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，按其中章节编号与标题层级写目标文档。

## 读取

- 编辑、新增或重建目标文档前，先读本 skill 与 [assets/TEMPLATE.md](assets/TEMPLATE.md)，再列 `docs/L4/deployment/` 的实际目录树。
- 读取应用架构文档，技术架构文档，以及对外接口文档和被调用第三方接口文档；对应 skill 为 `docs-application-architecture`、`docs-technology-architecture`、`docs-inbound` 与 `docs-outbound`。
- 读取目标文档、项目宪法和关联代码或配置，区分已落盘事实、待确认事项与部署资产现状。
- 文档按 L0 → L1 → L2 → L3 → L4 → common 生成，生成下层文档前先读上层产物；跨文档顺序与漂移清账由 `docs-align` skill 编排。
- 图使用 D2、Mermaid 或 ASCII 代码块直接写入 Markdown；容器式分层图遵循 `c4-container-diagram` skill，D2 图保留图名、视角、用途与边界等自描述信息，正文和注释使用中文。

## 生成流程

1. 先读 [assets/TEMPLATE.md](assets/TEMPLATE.md)，再按模板逐节写入项目事实，不在 SKILL 中另定结构。
2. 已有目标文档时，提取仍然有效的业务值，按模板重建章节、表格、图和命令，删除过期结构与旧图。
3. 依据应用划分、技术栈、接口契约和部署资产现状填写真实内容；没有事实依据的值不臆造。
4. 部署形态或版本标识机制存在歧义时询问用户；其余无歧义事项自主完成。
5. 部署资产只登记路径、归属、生效机制和用途，不移动或改写资产本体。
6. 生成后执行本 skill 的完成判定，并检查关联文档的一致性。

## 更新流程

- 编辑、新增、重建目标文档，或应用划分、技术栈、接口、外部服务、部署资产发生变化时进入更新流程。
- 先读目标文档与 [assets/TEMPLATE.md](assets/TEMPLATE.md)，再读发生变化的关联文档和资产；只修改受影响内容，保留仍有效的当前态信息。
- 章节删除或迁移后同步重编号并清理旧引用；发现文档与代码或配置不一致时以实际代码和配置为准修正文档。
- 涉及新的环境、部署形态、版本标识或资产归属时，先确认事实，再更新登记和关联说明。
- 更新完成后重新检查部署单元、环境、参数、版本、密钥和资产登记的一致性。

## 联动

- `docs-application-architecture` 的应用增减或应用边界变化，联动部署单元、环境说明与部署参数。
- `docs-technology-architecture` 的技术栈、运行时或存储方式变化，联动部署方式与运行形态。
- `docs-inbound` 的接口上线联动部署配置与验证入口；`docs-outbound` 的外部服务、密钥或回调变化联动对应部署配置。
- 部署脚本、compose、配置文件或 `.env` 资产变化，联动目标文档中的资产登记；资产生成、维护和实际部署执行统一交 `deploy-ops` skill。
- 测试期访问系统仍经 `tools` skill；部署与发布期的健康检查和冒烟验证由 `deploy-ops` skill 执行，属于系统访问约束的部署期豁免。
- 跨文档生成顺序、漂移扫描与一致性清账交 `docs-align` skill；本 skill 只负责部署说明书及其登记内容。

## 完成判定

以下全部通过才算完成：

- 目标文档按模板组织，标题与章节编号和层级一致，模板未定义的 frontmatter 或其他元信息不补写。
- 应用部署单元与 `docs-application-architecture` 的应用划分一致，部署单元数等于应用数。
- 环境矩阵、环境拓扑、各环境启动与发布说明相互一致，每个应用的参数、配置文件和健康检查入口齐全；环境名称只使用环境矩阵中的名称，standalone 与 dev 的运行形态边界保持一致。
- 版本标识机制明确，采用 SemVer 或 `BUILD_COMMIT` 机制并与发布流程一致，发布流程可定位到实际脚本或命令，回滚方式在部署单元与操作说明中完整可追溯。
- 正文只保留面向读者的业务内容，不写模板指引、构建元信息、占位符、填充说明或治理套话；同一信息只维护一处，跨层引用按项目宪法方向组织。
- 真实凭据、口令和 token 未写入文档或配置模板；`.env.example` 恒为占位值，真实 `.env` 不入库，密钥不落日志或前端包。
- `docs/L4/deployment/` 的 compose、Dockerfile、nginx、脚本、配置文件和 `.env` 资产均已登记路径、归属与生效机制，资产本体未被移动。
- 关联的架构、接口、集成和部署资产信息已完成一致性检查。
- 正文无 `SSOT`、单一事实源或唯一事实源字样，无加粗与 emoji，图均为可编辑文本。

## 边界

- 只维护 `docs/L4/DEPLOYMENT.md` 的文档内容与 `docs/L4/deployment/` 的资产登记，不修改部署资产文件本体。
- 不执行部署、不生成或维护部署脚本、compose、多环境 `.env`，上述工作归 `deploy-ops` skill。
- 不修改业务代码，不写入真实主机、口令、token 或其他凭据，不自动 commit 或 push。
- 目录、接口、应用或配置的跨文档对齐与迁移由 `docs-align` skill 负责；本 skill 不替代该编排职责。
- 数据库迁移按项目实际工具执行：已应用 revision 不再改，默认值使用字面量，发布前本地先完成 upgrade head 自测，发布顺序为覆盖代码、执行迁移、recreate 容器，迁移失败即中断。
- 环境 host 不写死，前端入口和测试连接参数通过工具配置或已登记的环境配置提供。
- 文档只写项目当前事实；历史与决策原因归 Git 历史，不在正文中保留过期占位。
