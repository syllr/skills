# README 文档更新规范（L1 产品层）

**本文档在修改 `README.md` 时生效。** 目标：按下方模板生成/更新 `README.md`，使其结构符合模板契约，保持 SSOT、不漂移、不遗漏联动。

## 触发条件

当以下任一情况发生时，本规则必须生效：

- 编辑、新增或重建 `README.md`
- 该文档关联的其他文档（见模板 `related`）发生变化，需要联动更新本文档
- 用户要求"生成/更新 README"

## 执行流程

1. **读模板 generation 元数据**：下方「模板全文」的 frontmatter `generation` 块是本文档的"生成/更新提示词"，逐字段执行：
   - `scan`：自主扫描列出的源（不问用户），作为更新依据
   - `ask_user`：仅当列出的决策点存在歧义时，才用询问工具问用户
   - `flow`：按列出的流程分支执行（全量重建 or 增量修改）
   - `reentrant`：支持可重入——全量重生成或增量修改都要能处理
   - `notes`：注意点（怎么生成，避免常见错误）
   - `checks`：生成后逐条反向核对（含 S8：文档不含 emoji）
   - `related`：关联模板与联动修改——更新本文档时，检查并同步 `related` 列出的关联文档
2. **按模板正文生成**：以下方「模板全文」的 Markdown 正文为结构基准，把模板复制为 `README.md`，按 `> 【指引】` 填写，**删除 generation 元数据块与全部 `> 【指引】` 说明**（实例不含这两者）。
3. **反向 check**：逐条执行模板 `generation.checks`，全部通过才算完成。

## 硬性要求

- **SSOT**：模板是本文档的唯一结构源；已合并/已删除的模板（如 DATA-ARCHITECTURE 已并入 DOMAIN-MODEL）不生成独立文档。
- **不用 emoji**（S8，grep 校验：`grep -P "[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}]" <文档>`）。
- **联动**：`related` 列的关联文档必须同步检查；跨层引用单向向下，下层不链回上层。
- **图规范**：文档中的图按模板要求用 D2 / Mermaid / ASCII，绘制规范见 CONSTITUTION §3.2。

## 完成判定

模板 `generation.checks` 全部通过 + 文档与关联文档无漂移。

## 模板全文（本 rule 的生成依据）

以下是 `README` 的完整模板（frontmatter generation 元数据 + Markdown 正文，SSOT，来自 references/templates/L1/README.template.md）：

```markdown
---
title: README — 项目入口
doc_type: template
layer: L1
description: L1 产品层 文档 README 的更新规范——修改 README.md 时触发，按模板 generation 元数据生成或更新该文档
globs:
  - "README.md"
# 生成提示词（元信息 · 仅模板持有，实例不含本块）
generation:
  # 自主判断（AI 扫描，不问用户）：当前项目路径 = 工作目录；是否已有 README = 扫描根目录
  scan:
    - 当前项目路径 = 工作目录（不问用户）
    - 扫描项目根，判断是否已有 README
    - 若已有：对照本模板结构判断是否符合（章节是否齐全）
  # 只有需要用户决策的才问（用询问工具）
  ask_user:
    - 生成时点：项目代码还没写（对话生成，用户描述需求）还是代码已写完（扫描项目自动生成）？让用户选
    - 已有 README → 参考/融入旧 README 的有效信息，但结构一定按本模板重建（不保留旧结构）
  flow: # 生成流程（分支）
    - 扫描项目（自主）：路径 + 已有/无 README
    - 问生成时点（对话生成 vs 项目自动生成）
    - 对话生成（代码未写）→ 与用户对话获取项目信息（一句话目标/技术栈/文档索引）→ 按模板新建
    - 项目自动生成（代码已写）→ 扫描项目（代码/文档/配置）→ 按模板生成
    - 已有 README → 融入旧 README 的有效信息（历史/背景/已知决策），但结构按本模板重建
  reentrant: # 可重入（不在乎 token，全量/增量都要支持）
    - 全量重生成：AI 收到"生成 README" → 无视已有结构，从模板完整重建（可融入旧 README 信息，但结构是新的）
    - 增量修改：已有 README 且符合模板 → 只更新变化部分（新增功能/技术栈变更/文档增删），保留未变内容
  notes: # 生成注意点
    - README 定位 = 项目是什么 + 技术栈 + 文档索引（只做入口，不承载内容）
    - 文档索引按 CONSTITUTION §3.1（L0-L4 + common 层），与实际文档一致
    - 技术栈只列事实，理由记 ADR
    - 与具体技术栈/框架无关（模板）
  checks: # 生成后反向 check
    - "README 定位正确（是什么+技术栈+索引，无冗余内容）"
    - "文档索引与实际文档一致（L0-L4 + common 层，路径正确）"
    - "技术栈与项目实际一致"
    - "README 与 CONSTITUTION §3.1 文档架构不冲突"
    - "S8：文档不含 emoji（grep 检查通过，详见 CONSTITUTION S8 依据）"
  related: # 关联模板与联动修改
    CONSTITUTION: 文档架构 SSOT 在它 §3.1，文档增删需同步 README 索引
    STRUCTURE: 目录结构 SSOT 在它 §1，目录变化需同步 README 路径
    USER-STORY: §5 UI 结构与交互点，新增 UI 时需同步
---
```
