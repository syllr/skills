# 组装规则（assembly · rule 生成细则）

> 本文件是 doc-arch-rules skill 的**组装细则**——定义「模板 → rule」的精确映射（占位符映射 + 模式 A/B 组装模板 + 组装硬约束 + 内容纯净/三层处置/完成判定机器校验）。**影响 rule 组装产物的内容在此（SSOT）**，SKILL.md 只留流程骨架；修改本文件 = 组装逻辑变化（implHash 刷新，全部 rule 需重新生成）。主流程见 [SKILL.md](../SKILL.md)。

```markdown
## 硬性要求

- <notes 内容逐条列出>
- **联动**：更新时按 related 同步关联文档（见触发条件）；跨层引用单向向下，下层不链回上层
- **图规范**：按 skill `references/diagram-spec.md` 用 D2 / Mermaid / ASCII（宪法 §3.2 指向该文件）
- **内容纯净（写法约束与构建提示归 rule，实例文档只承载业务内容）**——两层判定，逐行过：
  1. **构建元信息不进实例**：模板正文里 `> 【指引】` / `> 【模板使用指引】` / `> 【填写指引】` 等【】标记行是**生成提示**，只服务于"怎么填"，**仅存在于本 rule 的「模板」章节，生成/更新实例文档时一律不得写入实例**。
  2. **写法约束不进实例正文**：「这个文档应该怎么写/怎么画」的规范——编码规则、图例怎么画、条目编号约定、SSOT 声明的逐条重复（如每个故事重复"AC 在此定义（SSOT）"、"1:N 顿号分隔"）、格式约定——**归 rule 四节正文（notes/硬性要求）定义一次，实例正文不逐字重复**；实例只写业务内容（故事/AC/选型/聚合/能力），写法规范统一由 rule 指挥。
  3. **边界（防过度剔除）**：**面向读者的定义与判断口诀属业务内容，必须落实例正文**——如实体/值对象定义、规则类型（结构/行为/推导）定义、图例、AC 主路径 vs 时序图分支约定——读者读实例要能自懂，不能要求跳转 rule；判断标准：「读者理解这份文档需要它吗？」需要 → 正文；只约束"AI 怎么生成" → rule。
- **模板正文三层处置（生成/更新实例时对模板每一行判定）**：
  - **剔除**：带【】标记的引导行（`> 【指引】` 等）；含"对应模板 §X 位 / checks 标 N/A / 按 <模板X> 模板 §X 要求 / 按主题实际替换 / 生成后校验"等**生成指令口吻**的表述；**写法约束的逐条重复**（编码规则说明、"AC 在此定义（SSOT）/1:N 顿号分隔"这类在每个条目重复的写法声明——精简为一次业务提及或删除，规范由 rule 承载）→ 实例中删掉，或改写为面向读者的业务说明（如"本主题无精度分层，故 §3 承载选型依据"，而非"对应模板 §3 位"）。
  - **改写**：占位符（`<模块_xx>` `<模型_xx>` `<项目名>`）替换为真实业务名称；示例图/示例表换成实际内容，删掉"示例为…其他主题按实际替换"这类填充说明；删除占位示意行（`| ... | — | 按主题补充 |`）。
  - **保留**：面向读者的原则/元信息（"只写意图+边界""代码即真相"、SSOT 声明、"本图为 X 图"图标注、**定义与判断口诀**（实体/值对象、规则类型等读者需自懂的内容）、frontmatter 的 title/doc_type/layer）→ 保留，但要转成业务表述，不保留"按模板填写"口吻。

## 模板（生成/更新文档的结构基准）

以下为 `<target>` 的模板正文（不含 YAML frontmatter）。**本模板 = 生成提示 + 业务骨架 的混合体**：`> 【指引】` 等【】标记行是**构建元信息**（告诉你怎么填，仅存在于 rule，不写入实例）；其余（章节骨架、表头、示例图/表、原则说明）是**业务骨架**（生成实例时保留结构、替换为真实业务内容）。生成/更新 `<target>` 时严格按「硬性要求 · 模板正文三层处置」执行：**剔除**构建提示与生成指令、**改写**占位符与示例为实际内容、**保留**并正文化面向读者的原则/元信息。实例文档最终只承载业务内容，不含任何 `> 【指引】` 等构建说明。

<模板 Markdown 正文>
```

## 组装规则（硬约束）

- frontmatter 的 `description`/`alwaysApply`/`globs` **逐字抄**模板 omo 字段，不推导、不改写
- 四节正文**必须覆盖** generation 全部字段信息（tools/related/ask_user/flow/notes/checks 逐条内联，related 保留"文档名+联动说明"配对）
- 「模板」章节**只放剥离 YAML frontmatter 后的 Markdown 正文**（保留 `> 【指引】` 行——注意此为 rule 内生成提示，**供 rule 读者（生成实例的 AI）参考，绝不写入实例文档**；生成实例时按「内容纯净/三层处置」剥离）
- **rule 内禁止出现 YAML frontmatter 的 generation 原始块**（`---` 内 YAML dump）；generation 信息一律以自然语言四节形式存在
