# 组装规则（assembly · rule 生成细则）

> 本文件是 doc-arch-rules skill 的组装细则——定义「模板 → rule」的精确映射（占位符映射 + 模式 A/B 组装模板 + 组装硬约束 + 内容纯净/三层处置/完成判定机器校验）。影响 rule 组装产物的内容在此（SSOT），SKILL.md 只留流程骨架；修改本文件 = 组装逻辑变化（implHash 刷新，全部 rule 需重新生成）。主流程见 [SKILL.md](../SKILL.md)。

## 占位符映射（组装前先查表，消除对 `<DOC>/<层中文>/<target>` 的猜测）

| 占位符      | 取值                                                                                                                                                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LAYER_ZH`  | constitution→宪法，L1→L1 产品层，L2→L2 架构层，L3→L3 契约层，L4→L4 交付层，common→common 贯穿层（同 scripts/parse-template.mjs）；子目录继承父层中文（如 L2/deep-dives→L2 架构层；research 同理继承 L2） |

## 硬性要求

- <notes 内容逐条列出>
- 联动：更新时按 related 同步关联文档（见触发条件）；跨层引用单向向下，下层不链回上层
- 图规范：按 skill `references/diagram-spec.md` 用 D2 / Mermaid / ASCII
- 内容纯净（写法约束与构建提示归 rule，实例文档只承载业务内容）——两层判定 + 两条边界，逐行过：
  1. 构建元信息不进实例：模板正文里 `> 【指引】` / `> 【模板使用指引】` / `> 【填写指引】` 等【】标记行是生成提示，只服务于"怎么填"，仅存在于本 rule 的「模板」章节，生成/更新实例文档时一律不得写入实例。
  2. 写法约束不进实例正文：「这个文档应该怎么写/怎么画」的规范——编码规则、图例怎么画、条目编号约定、SSOT 声明的逐条重复（如每个故事重复"AC 在此定义（SSOT）"、"1:N 顿号分隔"）、格式约定——归 rule 四节正文（notes/硬性要求）定义一次，实例正文不逐字重复；实例只写业务内容（故事/AC/选型/聚合/能力），写法规范统一由 rule 指挥。
  3. 边界（防过度剔除）：面向读者的业务概念定义属业务内容，必须落实例正文——如规则类型（结构/行为/推导）定义、图例、AC 主路径 vs 时序图分支约定——读者读实例要能自懂，不能要求跳转 rule；建模方法论（对象类型判据/判断口诀/DDD 模式标准表/事件原则/决策速查类）归 rule 模板【指引】，实例不写；判断标准：「读者理解这份文档需要它吗？」需要 → 正文；「只约束 AI 怎么生成/建模」 → rule。
  4. 产物禁用 SSOT 标签：实例文档正文禁止出现「SSOT / 单一事实源 / 唯一事实源」字样，相关职责一律改为自然引用（见 §X / 详见文档 §Y / 统一维护），不写"XX SSOT 在 YY"这类标签式声明；SSOT 定义只保留在宪法 §2.2，产物只做自然引用不重复标签。
  5. 实例禁用加粗与 emoji：实例文档正文不得出现「加粗」与任何 emoji（强调靠句式与小节结构，不靠加粗；状态用文字词如已实现/待规划，不用表情符号）；机检：`grep -rnE '\*\*[^*`]+\*\*' <target>` 无输出（glob 通配符不成对不误报）+ emoji 扫描无输出（命令见 skill 仓 AGENTS.md NOTES）。
- 模板正文三层处置（生成/更新实例时对模板每一行判定）：
  - 剔除：带【】标记的引导行（`> 【指引】` 等）；含"对应模板 §X 位 / checks 标 N/A / 按 <模板X> 模板 §X 要求 / 按主题实际替换 / 生成后校验"等生成指令口吻的表述；写法约束的逐条重复（编码规则说明、"AC 在此定义（SSOT）/1:N 顿号分隔"这类在每个条目重复的写法声明——精简为一次业务提及或删除，规范由 rule 承载）→ 实例中删掉，或改写为面向读者的业务说明（如"本主题无精度分层，故 §3 承载选型依据"，而非"对应模板 §3 位"）。
  - 改写：占位符（`<模块_xx>` `<模型_xx>` `<项目名>`）替换为真实业务名称；示例图/示例表换成实际内容，删掉"示例为…其他主题按实际替换"这类填充说明；删除占位示意行（`| ... | — | 按主题补充 |`）。
  - 保留：面向读者的原则/元信息（"只写意图+边界""代码即真相"、"本图为 X 图"图标注、定义与判别说明（规则类型、图例、术语定义等读者需自懂的内容；DDD 建模判据/判断口诀除外——归上文第 3 点「边界」的建模方法论，实例不写）、目录职责类判断说明（如 STRUCTURE infra/integration 归属判别）属读者内容归正文）→ 保留，但要转成业务表述，不保留"按模板填写"口吻；实例 frontmatter 仅按模板正文明示规范生成（如 ADR 四键 title/doc_type/layer/status），无明示的不生成。

## 组装规则（硬约束）

- frontmatter 的 `description`/`alwaysApply` 逐字抄模板 omo 字段，不推导、不改写；`globs` 基线保护 + 允许扩展：模板 globs 为基线——功能 1 初始化时逐字抄，AI 不得删除/改写基线条目；扩展条目由 docs-align skill 的 globs 双向同步统一增删（不经本 skill，见 SKILL.md「定位」）：追加条目必须真实存在于磁盘，指向已删目录的条目随同步清理；update/rebuild 合并时必须保留仍存在的扩展条目（基线以模板为准重写，扩展做并集保留）；写法与匹配语义见 [globs 语法与用法](globs.md)
- 四节正文必须覆盖 generation 全部字段信息（tools/related/ask_user/flow/notes/checks 逐条内联，related 保留"文档名+联动说明"配对）
- 「模板」章节只放剥离 YAML frontmatter 后的 Markdown 正文（保留 `> 【指引】` 行——注意此为 rule 内生成提示，供 rule 读者（生成实例的 AI）参考，绝不写入实例文档；生成实例时按「内容纯净/三层处置」剥离）
- rule 内禁止出现 YAML frontmatter 的 generation 原始块（`---` 内 YAML dump）；generation 信息一律以自然语言四节形式存在
- 模板附属资产目录（仅 TEST-PLAN 模板持有）：`references/rule-assets/test-asset/`（卡模板 api-case/flow-case + 工具规范 test-tools.md + 参考实现 test-tools/）是 TEST-PLAN rule 的附属资产——每次全量同步整目录原样复制到项目（不判 TEST-PLAN 指纹是否最新，无条件覆盖） `.omo/rules/docs/test-asset/`（拷贝，不做占位符组装/三层处置/翻译；资产文件无 frontmatter、无 globs，规则引擎不应用，纯供 rule 触发后生成测试资产时参考——test-asset 是参考模板层，它参考生成的 docs/test/ 业务产物是产物层，同步时绝不覆盖）；rule「模板」章节内以相对链接 `test-asset/xxx` 引用资产文件——目录不随 rule 同步即死链，故为落盘必做项；已有目录直接整目录覆盖（无脑覆盖语义，见 SKILL.md「定位」——资产是 skill 侧模板副本，无项目侧手工改动语义）
