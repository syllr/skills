### 5.3 流程测试用例（Gherkin）

> 【指引】**用户旅程级测试**（像真实用户一样打开页面→点击→输入→验证）。用 Gherkin 中文（Given/When/Then）写成**可执行规范**——AI/自动化工具可据此执行（Playwright 浏览器自动化 + `toHaveScreenshot()` 截图视觉断言 + Trace 回放取证）。每条流程用例对应一个用户故事场景（RTM）。
> **文件落盘**：`tests/features/<模块>.feature`（每个流程用例一个 `.feature` 文件，与用例 ID 对应）。

```gherkin
# language: zh-CN
# @<用户故事场景> @<聚合名> @FLOW-<模块>-<序号>
功能: <业务功能名>
 作为 <角色>
 我想要 <目标>
 以便 <业务价值>

 背景:
 假设 浏览器已打开 <入口页面 URL>

 场景: <场景名>
 当 <操作 1>
 并且 <操作 2>
 那么 <预期结果 1（页面元素/文本/URL）>
 并且 <预期结果 2>
```

> **场景大纲示例**（参数化，对应指引④）：`场景大纲: <场景名>` + `例子:` 表（列 = 占位符 `<x>`，行 = 参数组合）。

```gherkin
 场景大纲: <输入 <类型> 生成 <类型>>
 当 用户输入 <类型>
 并且 点击「生成」
 那么 结果区展示 <类型> 内容
 例子:
  | <类型>       |
  | 文章         |
  | 视频脚本     |
```

> 【填写指引】① 每个用户故事主路径一个场景；② Then 断言页面**可观测输出**（元素/文本/URL/截图），不断言数据库；③ 需要视觉验证的场景加「并且 页面截图与基准一致（toHaveScreenshot）」；④ 参数化场景用「场景大纲 + 例子」表。
