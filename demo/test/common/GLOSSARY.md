# GLOSSARY 文档更新规范（common 贯穿层）

## 触发条件

当以下任一情况发生时，本规则必须生效：

- 编辑、新增或重建 `docs/common/GLOSSARY.md`
- 关联文档变化需联动更新（来自 generation.related）：
  - `DOMAIN-MODEL`（领域术语在它 §3，新增领域术语需联动）
  - `PRODUCT`（能力/功能术语，能力增删需同步术语）
  - `CONSTITUTION`（图规范在它 §3.2，术语统一需对齐）
- 用户要求"生成/更新 GLOSSARY"

## 执行流程

1. **工具**：Markdown 表格（术语/含义/别称易混淆）
2. **扫描**（自主，不问用户）：
   - 扫描各文档：提取项目级通用术语（能力/功能/应用/模块/状态机/状态流转）
   - 读 DOMAIN-MODEL §3：领域术语（分工参考）
   - 扫描目标文档：GLOSSARY 是否已存在
3. **问用户**（仅当有歧义）：
   - 术语定义有争议时（如某词含义）→ 问用户
4. **生成流程**：
   - 扫描（自主）：扫各文档术语 + 领域术语 + 目标文档
   - 已有 GLOSSARY → 参考旧文档有效信息，但结构按本模板重建
   - 按模板生成：项目级术语表（含义/别称易混淆）

## 硬性要求

- 项目级通用术语只在本表维护（SSOT），其他文档引用不复制
- 领域业务术语在 DOMAIN-MODEL §3 通用语言表维护（领域特有）
- 别称/易混淆词列出禁止混用
- 不用 emoji
- **联动**：更新时按 related 同步关联文档（见触发条件）；跨层引用单向向下，下层不链回上层
- **不用 emoji**（S8，grep 校验）
- **图规范**：按 generation.tools 与 CONSTITUTION §3.2 用 D2 / Mermaid / ASCII

## 完成判定

以下全部通过才算完成（generation.checks 逐条）：

- 术语覆盖项目级概念（能力/功能/应用/模块/状态机/状态流转）
- 与 DOMAIN-MODEL §3 领域术语不冲突（分工明确）
- 别称/易混淆词有禁止混用标注
- S8：文档不含 emoji（grep 检查通过，详见 CONSTITUTION S8 依据）
